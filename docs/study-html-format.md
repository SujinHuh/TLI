# 공부 HTML 형식

이 문서는 면접 준비 질문/답변을 Markdown으로 정리한 뒤, 공부하기 쉬운 HTML 페이지로 변환할 때 사용하는 형식을 정의한다.
사용자가 "면접준비" 또는 "면접"이라는 표현으로 면접 대비 자료 정리를 요청하면 이 형식을 우선 적용한다.

## 목적

- 면접 질문을 단순 목록이 아니라 실제 답변 흐름 중심으로 정리한다.
- 질문별로 관련 개념, 답변 핵심, 답변 예시, 꼬리 질문, 주의할 점을 함께 본다.
- HTML에서는 꼬리 질문을 토글 형태로 접고 펼칠 수 있게 만든다.
- 다음 면접 준비 때도 같은 구조를 재사용한다.
- 최종 마무리 전에는 읽기 전용 서브 에이전트가 항상 별도로 검수한다.

## 저장 위치

Markdown 원본은 주제에 맞는 작업 폴더에 저장한다.

```text
interviews/company/회사명/interview-questions.md
```

예시:

```text
interviews/company/spade-company/interview-questions.md
```

HTML 배포본은 아래 위치에 저장한다.

```text
interviews/company/회사명/interview.html
```

예시:

```text
interviews/company/spade-company/interview.html
```

## 문서 전체 구조

```md
# 회사명 면접 예상질문

## 답변 방향
면접 전체에서 어떤 관점으로 답할지 정리한다.

## 답변을 풍부하게 만드는 반대/대안 개념
질문에 따라 꺼내 쓸 수 있는 비교 개념을 정리한다.

---

## 1. 큰 주제

파트 설명을 작성한다.

### 1-1. 질문

#### 관련 개념
- [개념명](#concept-개념명)

#### 답변 핵심
- 핵심 1
- 핵심 2

#### 답변 예시
실제 면접에서 말할 수 있는 자연스러운 답변을 문단으로 작성한다.

#### 꼬리 질문

<details>
<summary>꼬리 질문</summary>

답변 내용

</details>

#### 주의할 점
- 과장하면 안 되는 부분
- 확인하지 않은 사실
- 안전하게 표현해야 하는 부분

---

## 관련 개념 빠른 설명

<a id="concept-개념명"></a>

### 개념명

개념 설명

<a class="concept-back" href="#" onclick="history.back(); return false;">이전으로 돌아가기</a>
```

## 질문별 필수 섹션

각 질문은 아래 순서를 기본으로 한다.

1. `관련 개념`
2. `답변 핵심`
3. `답변 예시`
4. `꼬리 질문`
5. `주의할 점`

## 답변 방향 작성 기준

답변 방향에는 아래 내용을 포함한다.

- 이번 면접에서 보여줘야 할 관점
- 단순 구현 설명을 넘어서 설명해야 할 내용
- 모르는 내용을 단정하지 않고 확인하겠다고 말하는 기준
- 답변할 때 조심해야 할 표현

예시 흐름:

```text
제가 아는 범위는 여기까지입니다.
구조상으로는 이런 요소가 필요할 것 같습니다.
그래서 저는 이렇게 판단했습니다.
실제 업무에서는 공식 문서, 설정값, 로그, 실행 계획, 모니터링 지표로 확인하겠습니다.
```

## 반대/대안 개념 작성 기준

면접 답변을 깊게 만들기 위해 비교 가능한 개념을 정리한다.

```md
- 선택한 방식 vs 대안 방식
  - 선택한 방식의 장점과 한계, 대안 방식의 장점과 한계를 함께 적는다.
```

예시:

```md
- 수동 상태 변경 vs 배치 자동화
  - 수동 처리는 예외 대응이 유연하지만 누락과 시점 오류가 생기기 쉽다.
  - 배치 자동화는 일관된 상태 전이에 유리하지만 실패 시 재처리 기준과 실행 이력 관리가 필요하다.
```

## 꼬리 질문 작성 기준

꼬리 질문은 Markdown 원문에서도 접고 펼칠 수 있도록 `<details>` 형식을 사용한다.

```md
<details>
<summary>질문</summary>

답변

</details>
```

HTML 변환 시에는 아래처럼 렌더링한다.

```html
<details class="tail-answer">
  <summary>질문</summary>
  <div class="tail-body">
    <p>답변</p>
  </div>
</details>
```

## 관련 개념 링크 기준

질문 안의 관련 개념은 문서 하단의 개념 설명으로 이동하게 만든다.

```md
- [트랜잭션](#concept-트랜잭션)
```

하단 개념 설명은 anchor를 명시한다.

```md
<a id="concept-트랜잭션"></a>

### 트랜잭션

여러 작업을 하나의 논리적 작업 단위로 묶어 처리하는 방식이다.

<a class="concept-back" href="#" onclick="history.back(); return false;">이전으로 돌아가기</a>
```

## HTML 화면 기준

HTML은 공부용 문서처럼 읽기 편해야 한다.

- 상단에 `면접 공부용 HTML` 배지를 둔다.
- 원본 Markdown 경로를 표시한다.
- 본문은 흰 배경의 문서 영역으로 보여준다.
- 관련 개념 링크는 하단 개념 설명으로 이동한다.
- 꼬리 질문은 토글 UI로 접고 펼친다.
- 답변 예시의 핵심 키워드는 굵게 표시한다.
- 모바일에서도 문서가 깨지지 않게 한다.

## 주의할 점

- 실제로 하지 않은 일을 직접 한 것처럼 쓰지 않는다.
- 확인하지 않은 장애, 성능 개선 효과, 내부 정책을 단정하지 않는다.
- "제가 확인한 범위에서는", "구조상으로는", "설정과 로그 기준으로 확인하겠습니다"처럼 안전한 표현을 사용한다.
- 회사 내부 정보나 민감한 데이터는 그대로 쓰지 않는다.
- 예시는 식별할 수 없는 가상 데이터로 작성한다.

## 생성 후 확인 기준

최종 게시 승인 전의 HTML 렌더링과 동작 검증은 저장소 밖의 임시 디렉터리에서 수행한다. 임시 산출물은 Git 게시 대상이 아니며 저장소의 `interviews/` 파일을 만들거나 수정하지 않는다. 검증 과정에서 내용이나 구조를 수정했다면 수정된 최종본을 사용자에게 다시 보여주고 게시 승인을 받아야 한다.

- Markdown 원문에서 모든 질문에 `답변 핵심`, `답변 예시`, `꼬리 질문`, `주의할 점`이 있는지 확인한다.
- `<details>` 안에 빈 답변이 없는지 확인한다.
- 관련 개념 링크와 하단 anchor가 서로 맞는지 확인한다.
- HTML에서 꼬리 질문 토글이 정상 동작하는지 확인한다.
- 배포했다면 `http://서버주소/파일명.html`이 `200 OK`로 응답하는지 확인한다.

## 최종 검수 기준

- 공부 HTML 원본 Markdown과 HTML 배포본을 마무리하기 전에는 읽기 전용 서브 에이전트가 항상 최종 검수를 수행한다.
- 서브에이전트는 원문 의미가 바뀌지 않았는지, 확인하지 않은 사실이 단정되지 않았는지, 민감한 정보가 포함되지 않았는지 확인한다.
- 서브에이전트는 꼬리 질문 `<details>` 답변이 비어 있지 않은지, 관련 개념 anchor가 깨지지 않았는지, HTML 토글과 링크가 정상인지 확인한다.
- 서브에이전트는 문제점과 수정 제안만 반환하며 파일 수정, 배포, commit, push를 하지 않는다.
- 서브에이전트 검수 결과 문제가 있으면 작성자가 수정한 최종본을 다시 사용자에게 보여준다.
- 사용자가 검수된 최신 최종본을 확인한 뒤 `docs/study-log-workflow.md`에 정의된 최종 게시 승인 문구 중 하나를 실제 명령으로 사용한 경우에만 승인 파일의 commit과 push를 진행한다.
- 배포는 Git 게시 승인에 포함되지 않으며 사용자가 별도로 명시적으로 요청한 경우에만 진행한다.
