# 학습 기록 검수 기준

이 문서는 AI 에이전트가 대화 원문을 `daily/`와 `concepts/`로 옮기기 전에 수행하는 검수 기준을 정의한다.
검수는 작성자와 분리된 별도 검수 역할(서브 에이전트)이 반드시 읽기 전용으로 수행한다.

## 목적

- 원본 대화의 의미가 요약 과정에서 바뀌지 않게 한다.
- `daily`와 `concepts`에 들어가는 내용을 사용자 의도에 맞게 유지한다.
- `git`에 올라가기 전에 위험한 오개념과 누락을 줄인다.

## 검토 기준

1. 원본에서 말한 원인과 결과가 요약에서 뒤바뀌지 않았는지 확인한다.
2. 핵심 결론이 잘못 바뀌지 않았는지 확인한다.
3. 중요한 맥락이 누락되지 않았는지 확인한다.
4. 원본에는 없던 내용이 추가되지 않았는지 확인한다.
5. 학습 기록으로 남기면 위험한 오개념이 없는지 확인한다.
6. 원본 표현과 요약 표현의 대응 관계가 자연스러운지 확인한다.
7. 사실 확인과 표현 정리를 섞지 않았는지 확인한다.
8. `daily`와 `concepts`로 나눌 때 의미가 달라지지 않았는지 확인한다.
9. 회고가 맞춤법, 띄어쓰기, 문장부호, 줄바꿈, 어휘, 표현 순서를 포함해 사용자 원문과 정확히 일치하는지 확인한다.
10. 공부 시간이 사용자 제공 시간을 우선했는지, 추정 시간이라면 그 사실이 표시되었는지 확인한다.
11. 기존 파일의 포맷, 사용자 원문, 추가 섹션이 손상되거나 누락되지 않았는지 확인한다.
12. 게시 대상이 사용자가 승인한 파일 경로로만 제한되어 있는지 확인한다.

## 검수 순서

1. 원본 대화와 초안을 나란히 놓고 읽는다.
2. 검토 기준에 따라 차이가 있는 부분을 표시한다.
3. 차이가 단순 요약인지, 의미 변경인지 구분한다.
4. 의미 변경, 누락 또는 오개념 가능성이 있으면 문제점과 수정 제안을 작성자에게 반환한다. 검수자가 파일이나 초안을 직접 수정하지 않는다.
5. 작성자가 검수 결과를 반영한 최종 초안을 사용자에게 다시 보여준다.
6. 사용자가 검수된 최신 최종본을 확인하고 `docs/study-log-workflow.md`에 정의된 최종 게시 승인 문구 중 하나를 실제 명령으로 사용한 뒤에만 승인 파일의 생성과 `git add`, `git commit`, `git push`를 진행한다.

## 적용 범위

- `daily` 문서 초안
- `concepts` 문서 초안
- 관련 Concepts 후보 선정
- 회고 문구 반영
- 공부 시간 반영
- 공부 중 개념 질문에 대한 `쉬운 ver`와 `개발자 ver` 답변

## 주의할 점

- 검수자는 새 지식을 추가하는 역할이 아니다.
- 검수자는 작성자와 분리된 별도 역할로서 원문과 초안의 일치성을 확인해야 한다.
- 검수자는 읽기 전용이며 파일 수정, commit, push를 하지 않는다.
- 실제 서브 에이전트 검수를 수행하지 못했으면 검수했다고 표시하지 않는다. 이 경우 게시를 중단하고 사용자에게 알린다.
- 사용자 확인 없이 회고를 확정하지 않는다.
- 회고는 사용자의 명시적인 편집 요청과 교체 승인 없이 교정하거나 요약하지 않는다.
- 사용자 최종 승인 없이 파일 생성, commit, push를 진행하지 않는다.
- 검수된 최신 최종본이 제시된 뒤 사용자가 `docs/study-log-workflow.md`에 정의된 최종 게시 승인 문구 중 하나를 실제 명령으로 사용하면 AI 에이전트가 승인된 파일에 한해 `git add`, `git commit`, `git push`까지 진행한다.
- Codex 샌드박스 권한 확인창이 뜨는 경우에는 사용자가 직접 승인해야 한다.
- 개념 질문 답변을 검수할 때는 쉬운 비유가 과하게 단순화되어 오개념이 되지 않았는지 확인한다.
- 개발자 버전은 실제 구현, 시스템 설계, 면접 답변 관점에서 사용할 수 있는 수준인지 확인한다.
- 검수자가 수정안을 제시할 때는 새 주제로 임의 확장하지 않고, 오개념 정정과 누락 보완에 필요한 범위로 제한한다.

## 검수자 프롬프트

```text
지금까지의 원본 대화 내용과 최종 요약 결과물을 비교해줘.

검토 기준은 다음과 같아.
1. 원본에서 말한 원인과 결과가 요약에서 뒤바뀌지 않았는지
2. 핵심 결론이 잘못 바뀌지 않았는지
3. 중요한 맥락이 누락되지 않았는지
4. 원본에는 없던 내용이 추가되지 않았는지
5. 학습 기록으로 남기면 위험한 오개념이 없는지
6. 회고가 맞춤법, 띄어쓰기, 문장부호, 줄바꿈, 어휘, 표현 순서를 포함해 사용자 원문과 정확히 일치하는지
7. 공부 시간에서 사용자 제공 시간을 우선했고 추정값은 추정이라고 표시했는지
8. 기존 파일의 포맷, 사용자 원문, 추가 섹션을 보존했는지
9. daily와 concepts로 나누면서 의미가 달라지지 않았는지
10. 게시 대상이 사용자가 승인한 파일 경로로만 제한되었는지

문제가 있으면 어떤 부분이 왜 문제인지 설명하고,
작성자가 반영할 수 있는 수정 제안을 작성해줘. 파일이나 초안을 직접 수정하지 마.

가능하면 원본 대화의 표현과 대응되는 부분을 기준으로 검토해줘.
```

## 개념 질문 답변 검수자 프롬프트

```text
사용자의 개념 질문과 AI 에이전트의 답변을 비교해줘.

답변은 반드시 두 가지 버전으로 나뉘어야 해.
1. 쉬운 ver (15살이 이해할 수 있는 ver)
2. 개발자 ver

검토 기준은 다음과 같아.
1. 쉬운 ver가 비유와 일상 예시로 이해하기 쉽게 설명되었는지
2. 쉬운 ver의 단순화가 원래 개념을 왜곡하지 않았는지
3. 개발자 ver가 정의, 동작 흐름, 사용 이유, 주의할 점을 포함하는지
4. 개발자 ver가 면접 답변으로 사용할 수 있을 정도로 구체적인지
5. 저장소의 기존 docs, daily, concepts 내용과 충돌하지 않는지

문제가 있으면 어떤 부분이 왜 문제인지 설명하고,
작성자가 반영할 수 있는 수정 제안을 반환해줘. 파일이나 답변 초안을 직접 수정하지 마.
문제가 없으면 `검수 결과: 문제 없음`이라고 짧게 정리해줘.
```
