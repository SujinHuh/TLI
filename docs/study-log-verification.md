# 학습 기록 검수 기준

이 문서는 AI 에이전트가 대화 원문을 `daily/`와 `concepts/`로 옮기기 전에 수행하는 검수 기준을 정의한다.
검수는 작성자와 분리된 별도 검수 역할(서브 에이전트)이 반드시 수행한다.

## 목적

- 원본 대화의 의미가 요약 과정에서 바뀌지 않게 한다.
- `daily`와 `concepts`에 들어가는 내용을 사용자 의도에 맞게 유지한다.
- `git`에 올라가기 전에 위험한 오개념과 누락을 줄인다.

## 검토 기준

1. 원본에서 말한 원인과 결과가 요약에서 뒤바뀌지 않았는지 확인한다.
2. 핵심 결론이 잘못 바뀌지 않았는지 확인한다.
3. 중요한 맥락이 누락되지 않았는지 확인한다.
4. 원본에는 없던 내용이 추가되지 않았는지 확인한다.
5. 학습 기록으로 남기면 위험한 오개념이 없는지 확인한다.
6. 원본 표현과 요약 표현의 대응 관계가 자연스러운지 확인한다.
7. 사실 확인과 표현 정리를 섞지 않았는지 확인한다.
8. `daily`와 `concepts`로 나눌 때 의미가 달라지지 않았는지 확인한다.

## 검수 순서

1. 원본 대화와 초안을 나란히 놓고 읽는다.
2. 검토 기준에 따라 차이가 있는 부분을 표시한다.
3. 차이가 단순 요약인지, 의미 변경인지 구분한다.
4. 의미 변경 또는 오개념 가능성이 있으면 초안을 수정한다.
5. 수정된 초안을 사용자에게 다시 보여준다.
6. 사용자가 최종 승인하면 파일 생성과 `git` 반영을 진행한다.

## 적용 범위

- `daily` 문서 초안
- `concepts` 문서 초안
- 관련 Concepts 후보 선정
- 회고 문구 반영
- 공부 시간 반영

## 주의할 점

- 검수자는 새 지식을 추가하는 역할이 아니다.
- 검수자는 작성자와 분리된 별도 역할로서 원문과 초안의 일치성을 확인해야 한다.
- 사용자 확인 없이 회고를 확정하지 않는다.
- 사용자 승인 없이 파일 생성, commit, push를 진행하지 않는다.

## 검수자 프롬프트

```text
지금까지의 원본 대화 내용과 최종 요약 결과물을 비교해줘.

검토 기준은 다음과 같아.
1. 원본에서 말한 원인과 결과가 요약에서 뒤바뀌지 않았는지
2. 핵심 결론이 잘못 바뀌지 않았는지
3. 중요한 맥락이 누락되지 않았는지
4. 원본에는 없던 내용이 추가되지 않았는지
5. 학습 기록으로 남기면 위험한 오개념이 없는지

문제가 있으면 어떤 부분이 왜 문제인지 설명하고,
수정된 최종 요약본을 다시 작성해줘.

가능하면 원본 대화의 표현과 대응되는 부분을 기준으로 검토해줘.
```
