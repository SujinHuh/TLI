1. Java 기본 문법과 객체지향

1.Java에서 ==와 equals()의 차이를 설명하시오.

개념

동등성 비교는 Java 필기에서 매우 자주 나오는 기본 문제다. ==는 primitive에서는 값 비교, reference type에서는 참조 주소 비교다. equals()는 객체가 의미상 같은지를 비교하도록 재정의할 수 있는 메서드다.

답변

String처럼 equals()가 재정의된 클래스는 내용이 같으면 true가 될 수 있지만, 직접 만든 객체는 재정의하지 않으면 Object의 기본 동작처럼 주소 비교가 된다. 실무에서는 ID, 값 객체, Map key 비교에서 동등성 기준을 명확히 잡아야 한다. equals()를 재정의할 때는 반사성, 대칭성, 추이성, 일관성, null 비교 규칙도 지켜야 한다.

2.hashCode()와 equals()를 함께 재정의해야 하는 이유를 설명하시오.

개념

hashCode()는 해시 기반 컬렉션이 객체를 빠르게 찾기 위해 사용하는 정수 해시값이다. equals()가 true인 두 객체는 반드시 같은 hashCode를 가져야 한다는 규약이 있다.

답변

HashMap, HashSet은 먼저 hashCode로 버킷을 찾고, 같은 버킷 안에서 equals로 실제 동등성을 확인한다. equals만 재정의하고 hashCode를 재정의하지 않으면 같은 값으로 봐야 할 객체가 다른 버킷에 들어가 조회나 중복 제거가 깨질 수 있다. 그래서 값 객체를 Map key로 쓸 가능성이 있으면 두 메서드를 항상 함께 재정의해야 한다.

3.String, StringBuilder, StringBuffer의 차이를 설명하시오.

개념

String은 불변 객체이고, 문자열을 바꿀 때마다 새 객체가 만들어질 수 있다. StringBuilder와 StringBuffer는 내부 버퍼를 사용해 문자열을 누적 변경한다.

답변

단일 스레드에서 문자열을 반복 조합할 때는 StringBuilder가 적합하다. StringBuffer는 주요 메서드가 동기화되어 thread-safe하지만 그만큼 비용이 있어 일반적인 로컬 문자열 조합에는 과하다. 반복문에서 String += value를 많이 쓰면 객체 생성과 GC 부담이 커질 수 있으므로 Builder 계열을 고려한다.

4.Java의 primitive type과 wrapper type의 차이를 설명하시오.

개념

primitive type은 값 자체를 다루고 null을 가질 수 없다. wrapper type은 primitive를 객체로 감싼 타입이라 null, 제네릭, 컬렉션 사용이 가능하다.

답변

오토박싱/언박싱은 편하지만 반복 계산, 대량 데이터 처리, Map 연산에서 불필요한 객체 생성이나 NPE를 만들 수 있다. 예를 들어 Integer count = null; count++는 언박싱 과정에서 NullPointerException이 발생한다. 성능이 중요한 루프나 대량 집계에서는 primitive 사용 가능 여부를 먼저 검토한다.

6.final 키워드를 변수, 메서드, 클래스에 붙였을 때 각각의 의미를 설명하시오.

개념

final은 재할당, 재정의, 상속을 막아 의도를 명확하게 하는 키워드다. 변수에 붙으면 한 번만 할당할 수 있고, 메서드에 붙으면 override가 불가능하며, 클래스에 붙으면 상속이 불가능하다.

답변

참조 변수에 final을 붙여도 객체 내부 상태까지 불변이 되는 것은 아니다. 불변 객체를 만들려면 필드를 private final로 두고, setter를 제거하고, 가변 객체를 방어적 복사해야 한다. 실무에서는 값 객체, 설정 객체, 의존성 필드에 final을 사용해 코드 안정성을 높인다.

개념

11.접근 제어자 private, default, protected, public의 범위를 설명하시오.

개념

접근 제어자는 클래스, 필드, 메서드, 생성자에 접근할 수 있는 범위를 제한하는 Java 문법이다. private은 같은 클래스 내부, default는 같은 패키지, protected는 같은 패키지와 상속 관계의 하위 클래스, public은 어디서든 접근 가능하다.

답변

캡슐화를 지키려면 필드는 보통 private으로 숨기고 필요한 동작만 메서드로 공개한다. public을 남발하면 내부 구현이 외부 코드와 강하게 결합되어 변경이 어려워진다. 같은 패키지에서만 협력하는 구현 클래스는 default, 상속 확장 지점은 신중하게 protected를 사용한다.

12.불변 객체가 필요한 이유와 만드는 방법을 설명하시오.

개념

불변 객체는 생성 후 내부 상태가 바뀌지 않는 객체다. 상태 변경이 없기 때문에 동시성 환경에서 안전하고, 값 객체로 사용할 때 예측 가능성이 높다.

답변

불변 객체를 만들려면 클래스를 상속 불가능하게 하거나 변경 지점을 막고, 필드를 private final로 선언하며, setter를 제공하지 않는다. 생성자에서 모든 값을 초기화하고, 내부에 List, Date 같은 가변 객체가 있으면 방어적 복사와 불변 뷰를 사용해야 한다. 예를 들어 금액, 기간, 좌표, 요청 조건 같은 값은 불변 객체로 만들면 Map key 사용과 멀티스레드 공유가 안전해진다.

15.Checked Exception과 Unchecked Exception의 차이를 설명하시오.

개념

Checked Exception은 컴파일러가 처리 여부를 강제하는 예외이고, Unchecked Exception은 RuntimeException 계열로 컴파일러가 처리를 강제하지 않는 예외다.

답변

Checked Exception은 파일, 네트워크, 외부 자원처럼 호출자가 복구나 대체 처리를 고려해야 하는 상황에 어울린다. Unchecked Exception은 잘못된 인자, 상태 오류, 비즈니스 규칙 위반처럼 코드 흐름에서 발생하는 오류에 많이 쓴다. 실무에서는 예외를 무조건 삼키지 말고 원인, 요청 식별자, 입력 조건을 로그로 남기며 계층 경계에서 의미 있는 예외로 변환해야 한다.

16.예외를 무조건 RuntimeException으로 감싸는 방식의 장단점을 설명하시오.

개념

Checked Exception을 RuntimeException으로 감싸면 메서드 시그니처가 단순해지지만, 호출자가 반드시 처리해야 하는 실패 가능성이 숨겨질 수 있다.

답변

장점은 서비스 계층 코드가 불필요한 throws 선언으로 오염되지 않고 트랜잭션 rollback 정책과 맞추기 쉽다는 점이다. 단점은 외부 API 실패, 파일 처리 실패처럼 복구 가능한 오류도 무시되기 쉬워 장애 원인 파악이 어려워질 수 있다는 점이다. 감쌀 때는 원본 예외를 cause로 유지하고, 예외 타입을 업무 의미에 맞게 나누며, 재시도 가능 여부를 구분해야 한다.

18.deadlock이 DB에서 발생하는 예시와 해결 방법을 설명하시오.

개념

답변

비밀번호는 복호화 가능한 암호화보다 단방향 password hashing을 사용한다. salt를 계정별로 다르게 두고 bcrypt, scrypt, Argon2처럼 느린 해시 알고리즘을 사용해 brute force 비용을 높인다.

개념

답변

bcrypt는 cost factor로 계산 비용을 조절할 수 있고, scrypt와 Argon2는 메모리 비용까지 사용해 GPU 기반 공격을 어렵게 한다. 계정별 salt를 함께 사용해 같은 비밀번호라도 다른 해시가 나오게 해야 한다.

2.DB connection pool이 모두 사용 중인 상황에서 어떤 로그와 지표를 확인할지 쓰시오.

개념

DB 문제는 정합성, 성능, 동시성의 균형을 묻는 경우가 많다. 인덱스는 조회 성능을 높이지만 쓰기 비용과 저장 공간을 증가시키고, 트랜잭션은 ACID를 통해 데이터 일관성을 보장한다.

답변

실행 계획에서는 index 사용 여부, rows 추정치, join 방식, filesort/temp table 여부를 확인한다. isolation level은 dirty read, non-repeatable read, phantom read 같은 현상을 어디까지 막을지 결정한다. 운영 DB와 통계 DB를 분리하는 이유는 대량 조회와 배치가 실시간 트랜잭션 처리에 주는 부하를 줄이고 장애 영향 범위를 분리하기 위해서다.

3.특정 API에서 500 error가 증가했다. 배포, DB, 외부 연동, 트래픽 관점에서 확인 순서를 쓰시오.

개념

500 error 증가는 서버 내부 처리 중 예외가 늘었다는 뜻이므로 최근 변경과 의존성 장애를 함께 확인해야 한다.

답변

먼저 에러 발생 시각, API path, error code, exception type, trace id를 모아 공통 패턴을 찾는다. 최근 배포가 있으면 변경된 코드와 설정, feature flag를 확인한다. DB 관점에서는 connection pool 고갈, deadlock, slow query, 제약 조건 오류를 보고, 외부 연동 관점에서는 timeout, 5xx, 인증 실패를 본다. 트래픽 급증이 원인이면 rate limit, queue 적체, thread pool 포화 여부를 확인한다.

개념

Java의 모든 클래스는 명시적으로 다른 클래스를 상속하지 않으면 기본적으로 java.lang.Object를 상속한다.

답변

Object는 equals, hashCode, toString, getClass, wait, notify, notifyAll 같은 공통 메서드를 제공한다. 그래서 모든 참조 타입은 Object 타입으로 다룰 수 있다.

2.HashMap의 평균 조회 시간 복잡도는 무엇인가?

개념

HashMap은 key의 hashCode로 버킷 위치를 계산하고, 같은 버킷 안에서 equals로 최종 key를 찾는 자료구조다. 평균적으로 조회, 삽입, 삭제가 O(1)에 가깝지만 해시 충돌이 많으면 성능이 나빠진다.

답변

Java 8 이후에는 한 버킷에 충돌 노드가 많아지면 linked list가 tree 구조로 바뀌어 최악 성능을 완화한다. key는 hashCode와 equals가 안정적이어야 하며, key로 쓰는 객체의 필드가 변경되면 조회가 깨질 수 있다. 멀티스레드 환경에서는 일반 HashMap을 공유 쓰기하면 안전하지 않으므로 ConcurrentHashMap 같은 구조를 사용한다.

3.TCP는 연결형 프로토콜인가 비연결형 프로토콜인가?

개념

TCP는 연결형 프로토콜이다. 데이터를 보내기 전에 3-way handshake로 연결을 수립한다.

답변

TCP는 연결을 기반으로 순서 보장, 재전송, 흐름제어, 혼잡제어를 제공한다. 반대로 UDP는 비연결형 프로토콜이라 연결 수립 없이 datagram을 보내며, 신뢰성은 애플리케이션이 별도로 보완해야 한다.

4.HTTP 201은 어떤 의미인가?

개념

HTTP 201 Created는 요청이 성공했고 그 결과로 새로운 리소스가 생성되었음을 의미하는 상태 코드다.

답변

주로 POST 요청으로 리소스를 생성했을 때 사용한다. 생성된 리소스의 위치를 Location header로 함께 내려줄 수 있다. 단순 조회 성공은 200, 비동기 처리 접수는 202와 구분한다.

6.SELECT ... FOR UPDATE는 어떤 종류의 읽기인가?

개념

SELECT ... FOR UPDATE는 조회한 row에 배타적 lock을 거는 locking read다. 단순 조회가 아니라 이후 갱신을 전제로 다른 트랜잭션의 동시 변경을 막는다.

답변

재고 차감, 잔액 변경처럼 읽은 값을 기준으로 곧바로 수정해야 하는 경우에 사용한다. 트랜잭션이 끝날 때까지 lock이 유지될 수 있으므로 범위를 좁게 잡고 트랜잭션을 짧게 유지해야 deadlock과 대기 시간을 줄일 수 있다.

14.READ COMMITTED에서 non-repeatable read가 발생할 수 있는가?

개념

답변
