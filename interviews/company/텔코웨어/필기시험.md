# 텔코웨어 필기시험 대비

## 준비 방향

텔코웨어 필기시험은 일반 웹서비스 백엔드보다 **Java/Spring 기본기 + DB + 네트워크/통신 서버 이해** 쪽으로 나올 가능성이 높다.

근거는 다음과 같다.

- Java 백엔드 공고는 경력 3~5년, Spring Boot 기반 Web Application 백엔드 개발, Java, RDBMS, 빌드/배포, MSA/RESTful 이해를 요구한다.
- 텔코웨어는 IMS Solutions, 5G/LTE Core, Cloud, Security 쪽을 하는 통신 소프트웨어 회사다.
- 공식 홈페이지에 IMS Core 시스템, 5G/LTE Core, VNF/CNF 기반 이동통신 솔루션을 제공한다고 되어 있다.
- 5G Core 쪽에는 UDM, UDR, SEPP, NRF, UPF, HLR/HSS 같은 통신 Core 장비가 명시되어 있다.
- NRF는 5G Core NF 간 연동을 지원하는 시스템으로 설명되어 있다.

예상 난이도는 **5년차인데 Java/Spring/DB를 말로만 아는지, 서버 장애·트랜잭션·동시성·네트워크까지 이해하는지**를 보는 쪽일 가능성이 크다.

## 최우선 예상문제 TOP 30

### A. Java 예상문제

#### 1. JVM 메모리 구조를 설명하시오.

JVM 메모리는 크게 Method Area, Heap, Stack, PC Register, Native Method Stack으로 나뉜다.
객체는 주로 Heap에 생성되고, 지역변수와 메서드 호출 정보는 Stack에 쌓인다.
Method Area에는 클래스 메타정보, static 변수, 상수 풀 등이 저장된다.
GC는 주로 Heap 영역의 더 이상 참조되지 않는 객체를 정리한다.

꼬리질문: `new User()`를 하면 어디에 뭐가 생기는가?

답변 포인트:

- `new User()` 객체 자체는 Heap에 생성된다.
- 그 객체를 가리키는 참조변수는 지역변수라면 Stack 프레임에 저장된다.

#### 2. GC가 무엇이고, Minor GC와 Major GC 차이는?

GC는 더 이상 참조되지 않는 객체를 자동으로 회수하는 JVM 메모리 관리 기능이다.
Minor GC는 Young 영역에서 발생하고 비교적 빠르다.
Major GC는 주로 Old 영역을 대상으로 하고, Full GC는 Heap 전체와 Metaspace/Class metadata 등까지 포함할 수 있다.
세부 동작은 사용하는 GC 구현에 따라 달라질 수 있다.
Full GC가 잦으면 Stop-The-World 시간이 길어져 서비스 응답 지연이 발생할 수 있다.

#### 3. equals()와 hashCode()를 같이 재정의해야 하는 이유는?

`equals()`는 객체의 동등성을 비교하고, `hashCode()`는 해시 기반 자료구조에서 버킷 위치를 찾는 데 사용된다.
두 객체가 `equals()` 기준으로 같다면 반드시 같은 `hashCode()`를 반환해야 한다.
그렇지 않으면 `HashMap`, `HashSet`에서 같은 객체로 판단되지 않아 조회 실패나 중복 저장 문제가 발생할 수 있다.

#### 4. HashMap의 동작 원리를 설명하시오.

`HashMap`은 key의 `hashCode()`를 기반으로 배열의 인덱스를 계산하고, 해당 버킷에 key-value를 저장한다.
해시 충돌이 발생하면 Java 8 기준으로 처음에는 linked list로 관리하다가, 충돌이 많아지면 tree 구조로 전환될 수 있다.
평균 조회 시간은 O(1)이지만 해시 충돌이 심하면 성능이 떨어질 수 있다.

#### 5. HashMap과 ConcurrentHashMap의 차이는?

`HashMap`은 thread-safe하지 않다.
여러 스레드가 동시에 수정하면 데이터 정합성이 깨질 수 있다.
`ConcurrentHashMap`은 동시성 환경에서 안전하게 사용할 수 있도록 내부적으로 락 범위를 줄이거나 CAS 등을 활용한다.
전체 맵에 락을 거는 방식보다 성능이 좋다.
다만 복합 연산은 여전히 원자성을 직접 고려해야 한다.

#### 6. String, StringBuilder, StringBuffer 차이는?

- `String`: immutable이라 문자열을 변경할 때마다 새 객체가 생성된다.
- `StringBuilder`: mutable이고 동기화를 지원하지 않아 단일 스레드에서 빠르다.
- `StringBuffer`: mutable이면서 동기화를 지원해 thread-safe하지만 상대적으로 느릴 수 있다.

#### 7. checked exception과 unchecked exception 차이는?

checked exception은 컴파일 시점에 예외 처리 여부를 강제한다. 예를 들어 `IOException`이 있다.
unchecked exception은 `RuntimeException` 하위 타입으로 컴파일러가 처리를 강제하지 않는다.
예를 들어 `NullPointerException`, `IllegalArgumentException`이 있다.
비즈니스 로직에서는 복구 가능한 예외인지, 호출자가 처리해야 하는 예외인지에 따라 선택해야 한다.

#### 8. final 키워드의 의미는?

변수에 붙으면 재할당이 불가능하고, 메서드에 붙으면 오버라이딩이 불가능하며, 클래스에 붙으면 상속이 불가능하다.
다만 참조형 변수에 `final`을 붙였다고 해서 객체 내부 상태까지 불변이 되는 것은 아니다.
참조 대상만 바꿀 수 없다는 의미다.

#### 9. 오버로딩과 오버라이딩 차이는?

오버로딩은 같은 이름의 메서드를 매개변수 타입이나 개수 등을 다르게 해서 여러 개 정의하는 것이다.
컴파일 타임에 결정된다.
오버라이딩은 부모 클래스의 메서드를 자식 클래스에서 재정의하는 것이다.
런타임 다형성과 관련 있다.

#### 10. Java의 OOP 4대 특성을 설명하시오.

- 캡슐화: 데이터와 행위를 묶고 외부 접근을 제한하는 것
- 상속: 기존 클래스의 속성과 기능을 재사용하는 것
- 다형성: 같은 인터페이스나 부모 타입으로 여러 구현체를 다룰 수 있는 특성
- 추상화: 복잡한 내부 구현을 숨기고 핵심 역할만 드러내는 것

### B. Spring / Spring Boot 예상문제

#### 11. Spring IoC와 DI를 설명하시오.

IoC는 객체 생성과 의존관계 제어를 개발자가 직접 하지 않고 Spring Container가 담당하는 구조다.
DI는 필요한 의존 객체를 외부에서 주입받는 방식이다.
이를 통해 객체 간 결합도를 낮추고 테스트하기 쉬운 구조를 만들 수 있다.

#### 12. Bean의 생명주기를 설명하시오.

Spring Bean은 객체 생성, 의존성 주입, 초기화 콜백, 사용, 소멸 콜백 순서로 관리된다.
대표적으로 `@PostConstruct`, `InitializingBean`, `@PreDestroy`, `DisposableBean` 등을 사용할 수 있다.

#### 13. @Component, @Service, @Repository, @Controller 차이는?

모두 Spring Bean으로 등록되는 stereotype annotation이다.
`@Component`는 일반 컴포넌트이고, `@Service`는 비즈니스 로직 계층, `@Repository`는 데이터 접근 계층, `@Controller`는 웹 요청 처리 계층에 사용한다.
`@Repository`는 DB 예외를 Spring의 `DataAccessException` 계층으로 변환하는 기능과도 관련이 있다.

#### 14. @Transactional 동작 원리를 설명하시오.

Spring의 `@Transactional`은 AOP 프록시 기반으로 동작한다.
메서드 호출 전 트랜잭션을 시작하고, 정상 종료 시 commit, 롤백 대상 예외 발생 시 rollback을 수행한다.
기본적으로 unchecked exception 발생 시 rollback되고, checked exception은 별도 설정이 없으면 rollback되지 않는다.

#### 15. @Transactional이 동작하지 않는 대표 사례는?

같은 클래스 내부에서 `this.method()`처럼 자기 자신의 메서드를 호출하면 프록시를 거치지 않기 때문에 트랜잭션이 적용되지 않을 수 있다.
또한 private 메서드나 final 메서드에도 프록시 기반 AOP가 적용되기 어렵다.
트랜잭션 적용 여부는 외부에서 프록시 객체를 통해 호출되는지가 중요하다.

#### 16. Filter, Interceptor, AOP 차이는?

- Filter: Servlet Container 레벨에서 동작하며 Spring MVC에 들어오기 전 요청/응답을 처리한다. 인증, 인코딩, 로깅 등에 사용된다.
- Interceptor: Spring MVC의 DispatcherServlet 이후 Controller 호출 전후에 동작한다. 로그인 체크, 권한 검증 등에 사용된다.
- AOP: 비즈니스 로직의 공통 관심사를 메서드 단위로 분리할 때 사용한다. 트랜잭션, 로깅, 권한 검사 등에 활용된다.

#### 17. Spring MVC 요청 흐름을 설명하시오.

클라이언트 요청이 들어오면 Filter를 거쳐 DispatcherServlet으로 전달된다.
DispatcherServlet은 HandlerMapping을 통해 Controller를 찾고, HandlerAdapter를 통해 Controller를 실행한다.
Controller는 Service를 호출하고 결과를 반환한다.
JSON API라면 HttpMessageConverter가 객체를 JSON으로 변환해 응답한다.

#### 18. RESTful API란 무엇인가?

RESTful API는 자원을 URI로 표현하고, HTTP Method를 통해 자원에 대한 행위를 표현하는 API 설계 방식이다.
GET은 조회, POST는 생성, PUT은 전체 수정, PATCH는 부분 수정, DELETE는 삭제에 사용한다.
상태코드도 의미에 맞게 사용해야 한다.
예를 들어 성공 조회는 200, 생성은 201, 잘못된 요청은 400, 인증 실패는 401, 권한 없음은 403, 리소스 없음은 404를 사용할 수 있다.

#### 19. Spring Boot의 장점은?

Spring Boot는 자동 설정, 내장 WAS, starter dependency를 통해 설정 부담을 줄이고 빠르게 애플리케이션을 개발할 수 있게 해준다.
또한 운영 관점에서는 Actuator를 통해 상태 확인, 메트릭 확인, health check 등을 구성할 수 있다.

#### 20. Controller에서 Entity를 그대로 반환하면 왜 위험한가?

Entity는 DB 구조와 밀접하게 연결되어 있기 때문에 API 응답으로 그대로 노출하면 내부 구조가 외부에 드러날 수 있다.
또한 양방향 연관관계가 있을 경우 순환 참조 문제가 발생할 수 있고, Lazy Loading으로 인해 예기치 않은 쿼리가 발생할 수 있다.
그래서 보통 DTO로 변환해서 응답한다.

### C. DB / SQL 예상문제

#### 21. 인덱스의 장점과 단점은?

인덱스는 조회 성능을 높이기 위한 자료구조다.
WHERE, JOIN, ORDER BY 등에 사용되면 검색 범위를 줄일 수 있다.
단점은 INSERT, UPDATE, DELETE 시 인덱스도 함께 갱신해야 하므로 쓰기 성능이 떨어질 수 있고, 추가 저장공간이 필요하다는 점이다.
또한 컬럼 가공, 낮은 선택도, 잘못된 복합 인덱스 순서에서는 인덱스 효과가 떨어질 수 있다.

#### 22. 트랜잭션 ACID를 설명하시오.

- Atomicity: 전부 성공하거나 전부 실패해야 한다는 원자성
- Consistency: 트랜잭션 전후 데이터가 일관된 상태를 유지해야 한다는 일관성
- Isolation: 동시에 실행되는 트랜잭션이 서로 간섭하지 않아야 한다는 격리성
- Durability: commit된 데이터는 장애가 발생해도 보존되어야 한다는 지속성

#### 23. 트랜잭션 격리 수준을 설명하시오.

대표적으로 Read Uncommitted, Read Committed, Repeatable Read, Serializable이 있다.
Read Uncommitted는 commit되지 않은 데이터도 읽을 수 있어 dirty read가 발생할 수 있다.
Read Committed는 commit된 데이터만 읽지만 non-repeatable read가 발생할 수 있다.
Repeatable Read는 같은 트랜잭션 안에서 같은 row를 반복 조회할 때 결과 일관성을 보장한다.
다만 range query에서의 phantom read 처리 여부는 DBMS 구현에 따라 달라질 수 있다.
Serializable은 가장 강한 격리 수준이지만 동시성이 가장 낮다.

#### 24. Deadlock이 무엇이고 어떻게 줄일 수 있는가?

Deadlock은 두 개 이상의 트랜잭션이 서로 상대방이 점유한 락을 기다리면서 무한 대기하는 상황이다.
줄이려면 테이블이나 row 접근 순서를 일관되게 맞추고, 트랜잭션 범위를 짧게 유지하고, 필요한 인덱스를 만들어 불필요한 락 범위를 줄여야 한다.
또한 재시도 로직을 두는 것도 실무적으로 필요하다.

#### 25. Join 종류를 설명하시오.

INNER JOIN은 양쪽 테이블에 매칭되는 데이터만 조회한다.
LEFT JOIN은 왼쪽 테이블의 데이터는 모두 유지하고 오른쪽 테이블은 매칭되는 경우만 붙인다.
RIGHT JOIN은 오른쪽 테이블 기준이고, FULL OUTER JOIN은 양쪽 전체를 포함한다.
실무에서는 조회 기준이 되는 테이블을 명확히 잡고 JOIN 조건과 인덱스를 함께 봐야 한다.

#### 26. 정규화와 반정규화 차이는?

정규화는 데이터 중복을 줄이고 무결성을 높이기 위해 테이블을 구조화하는 과정이다.
반정규화는 조회 성능이나 개발 편의성을 위해 일부 중복을 허용하는 설계다.
정규화는 쓰기 정합성에 유리하고, 반정규화는 읽기 성능에 유리할 수 있지만 데이터 불일치 관리가 필요하다.

### D. 네트워크 / OS / 서버 예상문제

텔코웨어는 통신 솔루션 회사라서 이 파트가 중요할 수 있다.
공식 홈페이지에도 IMS, 5G/LTE Core, Cloud, VNF/CNF 기반 이동통신 솔루션이 핵심 사업으로 나와 있어서, 단순 CRUD 웹 백엔드보다 네트워크 기본기를 물어볼 가능성이 있다.

#### 27. TCP와 UDP 차이는?

TCP는 연결 지향 프로토콜이고 신뢰성, 순서 보장, 흐름 제어, 혼잡 제어를 제공한다.
대신 상대적으로 오버헤드가 크다.
UDP는 비연결형 프로토콜이고 신뢰성이나 순서 보장은 없지만 빠르고 오버헤드가 적다.
실시간 스트리밍, 음성, DNS 등에 사용된다.

#### 28. TCP 3-way handshake를 설명하시오.

클라이언트가 SYN을 보내고, 서버가 SYN+ACK를 응답하고, 클라이언트가 ACK를 보내면 연결이 성립된다.
이 과정은 양쪽이 통신 가능한 상태인지 확인하고 초기 sequence number를 교환하기 위한 절차다.

#### 29. HTTP와 HTTPS 차이는?

HTTP는 평문으로 데이터를 주고받는 프로토콜이다.
HTTPS는 HTTP에 TLS/SSL을 적용해 암호화, 무결성, 서버 인증을 제공한다.
로그인, 토큰, 개인정보가 오가는 서비스에서는 HTTPS가 필수다.

#### 30. L4 Load Balancer와 L7 Load Balancer 차이는?

L4 Load Balancer는 TCP/UDP 레벨에서 IP와 Port 기반으로 트래픽을 분산한다.
L7 Load Balancer는 HTTP 레벨에서 URL, Header, Cookie 같은 애플리케이션 정보를 기준으로 라우팅할 수 있다.
L4는 상대적으로 빠르고 단순하며, L7은 세밀한 라우팅과 정책 적용이 가능하다.

## 텔코웨어 맞춤형 고확률 문제

#### 31. MSA의 장점과 단점은?

MSA는 서비스를 독립적으로 배포하고 확장할 수 있다는 장점이 있다.
장애가 전체 시스템으로 번지는 것을 줄일 수도 있다.
단점은 서비스 간 통신, 트랜잭션 관리, 장애 추적, 배포 복잡도가 증가한다는 점이다.
그래서 MSA에서는 API 계약, 모니터링, 로그 추적, 장애 격리, 재시도 정책이 중요하다.

#### 32. REST API에서 멱등성이란?

멱등성은 같은 요청을 여러 번 보내도 결과가 동일한 성질이다.
GET, PUT, DELETE는 일반적으로 멱등하게 설계하고, POST는 보통 멱등하지 않다.
DELETE는 반복 호출 시 응답 상태코드가 달라질 수 있지만, 서버의 최종 상태가 같다면 멱등하다고 본다.
실무에서는 네트워크 재시도나 중복 요청이 발생할 수 있기 때문에 결제, 티켓 발급, 상태 변경 API에서는 멱등키를 두기도 한다.

#### 33. 동기 호출과 비동기 호출 차이는?

동기 호출은 요청한 작업이 끝날 때까지 호출자가 기다리는 방식이다.
구현은 단순하지만 지연이 전파될 수 있다.
비동기 호출은 요청 후 결과를 기다리지 않고 다음 작업을 진행하는 방식이다.
대량 처리나 외부 시스템 연동에서 유리하지만 실패 처리, 순서 보장, 재처리 설계가 필요하다.

#### 34. 장애가 난 외부 API를 호출해야 할 때 어떻게 설계할 것인가?

타임아웃을 반드시 설정하고, 재시도는 제한적으로 적용해야 한다.
계속 실패하는 경우 circuit breaker로 장애 전파를 막고, 실패 요청은 별도 저장 후 재처리할 수 있게 설계한다.
또한 로그와 모니터링을 통해 어느 외부 시스템에서 실패했는지 추적 가능해야 한다.

#### 35. 대량 트래픽 상황에서 서버를 안정적으로 운영하려면?

우선 병목 지점을 찾아야 한다.
DB 쿼리, 커넥션 풀, 스레드 풀, 외부 API, GC, 네트워크 지연 등을 확인한다.
DB에는 적절한 인덱스와 쿼리 개선이 필요하고, 애플리케이션에서는 캐싱, 비동기 처리, 타임아웃, 큐 기반 완충을 고려할 수 있다.
운영 관점에서는 메트릭, 로그, 알림, 장애 대응 절차가 필요하다.

#### 36. Connection Pool이 필요한 이유는?

DB 연결은 생성 비용이 크기 때문에 매 요청마다 새로 만들면 성능이 떨어진다.
Connection Pool은 미리 일정 수의 커넥션을 만들어두고 재사용해서 성능을 높인다.
다만 pool size가 너무 작으면 요청이 대기하고, 너무 크면 DB에 부담을 줄 수 있어 애플리케이션 스레드 수와 DB 자원을 고려해 설정해야 한다.

#### 37. Thread Pool이 필요한 이유는?

요청마다 스레드를 무한정 생성하면 메모리와 CPU context switching 비용이 커진다.
Thread Pool은 제한된 수의 스레드를 재사용해서 시스템 자원을 안정적으로 관리한다.
하지만 pool이 꽉 차면 요청이 대기하거나 거절될 수 있으므로 queue 크기, timeout, rejection policy를 함께 설계해야 한다.

#### 38. 서버에서 timeout 설정이 중요한 이유는?

외부 API나 DB 응답이 지연될 때 timeout이 없으면 스레드가 계속 대기하면서 전체 서비스 장애로 번질 수 있다.
timeout은 장애 전파를 막고 시스템 자원을 보호하기 위한 기본 방어선이다.
connect timeout, read timeout을 구분해서 설정해야 한다.

#### 39. 인증과 인가의 차이는?

인증은 사용자가 누구인지 확인하는 과정이다. 예를 들어 로그인이나 토큰 검증이다.
인가는 인증된 사용자가 특정 리소스나 기능에 접근할 권한이 있는지 확인하는 과정이다.
예를 들어 일반 사용자는 자신의 정보만 조회할 수 있고, 관리자는 전체 사용자 정보를 조회할 수 있다.

#### 40. JWT의 장점과 단점은?

JWT는 서버가 세션을 저장하지 않아도 사용자 정보를 검증할 수 있어 확장성이 좋다.
하지만 토큰이 탈취되면 만료 전까지 악용될 수 있고, 서버에서 즉시 무효화하기 어렵다.
그래서 access token은 짧게, refresh token은 안전하게 관리하고, 필요하면 blacklist나 token rotation을 사용한다.

## 코딩형 예상문제

### 1. 문자열에서 중복 문자 제거

문제: 문자열 `"banana"`에서 중복 문자를 제거하고 입력 순서를 유지하여 출력하시오.

```java
public static String removeDuplicate(String input) {
    Set<Character> seen = new LinkedHashSet<>();
    for (char c : input.toCharArray()) {
        seen.add(c);
    }
    StringBuilder sb = new StringBuilder();
    for (char c : seen) {
        sb.append(c);
    }
    return sb.toString();
}
```

출력:

```text
ban
```

### 2. Map에서 값 카운팅

문제: 문자열 배열에서 각 단어의 등장 횟수를 구하시오.

```java
String[] arr = {"java", "spring", "java", "db"};

Map<String, Integer> countMap = new HashMap<>();
for (String word : arr) {
    countMap.put(word, countMap.getOrDefault(word, 0) + 1);
}
```

결과:

```text
java=2
spring=1
db=1
```

### 3. List에서 짝수만 필터링

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5, 6);
List<Integer> result = numbers.stream()
        .filter(n -> n % 2 == 0)
        .toList();
```

결과:

```text
[2, 4, 6]
```

### 4. 코드 결과 예측

```java
String a = "hello";
String b = "hello";
String c = new String("hello");
System.out.println(a == b);
System.out.println(a == c);
System.out.println(a.equals(c));
```

정답:

```text
true
false
true
```

이유:

- `a`와 `b`는 문자열 리터럴이라 String Pool의 같은 객체를 참조한다.
- `c`는 `new`로 새 객체를 만들었기 때문에 참조값은 다르다.
- 문자열 내용은 같으므로 `equals()`는 true다.

### 5. NPE 발생 지점 찾기

```java
User user = null;
System.out.println(user.getName());
```

정답:

`user`가 null인데 `getName()`을 호출했기 때문에 `NullPointerException`이 발생한다.

개선:

```java
if (user != null) {
    System.out.println(user.getName());
}
```

또는 `Optional`을 사용할 수 있다.

```java
Optional.ofNullable(user)
        .map(User::getName)
        .ifPresent(System.out::println);
```

다만 실무에서는 null이 들어오지 않도록 메서드 계약과 검증을 먼저 잡는 것이 더 중요하다.

### 6. 트랜잭션 롤백 문제

```java
@Transactional
public void save() throws Exception {
    repository.save(data);
    throw new Exception();
}
```

문제: 기본 설정에서 rollback 되는가?

정답:

기본적으로 rollback되지 않는다.
Spring `@Transactional`은 기본적으로 unchecked exception인 `RuntimeException`, `Error`에 대해 rollback한다.
checked exception도 rollback하려면 아래처럼 설정한다.

```java
@Transactional(rollbackFor = Exception.class)
public void save() throws Exception {
    repository.save(data);
    throw new Exception();
}
```

## 텔코웨어 추가 통신/네트워크 문제

### 1. IMS가 무엇인지 아는가?

IMS는 IP Multimedia Subsystem의 약자로, IP 기반 멀티미디어 서비스를 제공하기 위한 통신망 구조다.
VoLTE, 영상통화, 메시징 같은 서비스를 제공하는 데 사용된다.
텔코웨어는 공식적으로 IMS Network 상의 Core 시스템을 제공한다고 설명하고 있고, CSCF, HSS, IBCF, TAS, MRF 같은 제품군을 보유하고 있다.

면접/필기에서는 깊은 통신 프로토콜까지보다 **통신 서비스는 안정성, 세션 관리, 인증/가입자 정보, 장애 대응이 중요하다** 정도로 연결하면 충분하다.

### 2. 5G Core에서 NRF가 하는 역할은?

NRF는 Network Repository Function이다.
5G Core의 NF, 즉 Network Function 인스턴스 정보를 관리하고, NF 간 서비스 탐색과 연동을 지원한다.
텔코웨어 공식 제품 설명에서도 NRF는 동적으로 변경되는 5G Core NF의 서비스 상태 모니터링과 IP/FQDN 등 연동 정보를 관리해 NF 간 상호 연동을 지원한다고 설명한다.

### 3. 통신 서버에서 안정성이 중요한 이유는?

통신 서버는 일반 웹서비스보다 장애 영향 범위가 크다.
가입자 인증, 세션 연결, 통화/데이터 서비스 연동 같은 핵심 기능이 지연되면 사용자 전체 서비스 품질에 영향을 줄 수 있다.
그래서 timeout, retry, failover, 이중화, 모니터링, 장애 격리 설계가 중요하다.

### 4. Stateful 서버와 Stateless 서버 차이는?

Stateful 서버는 세션이나 상태 정보를 서버가 직접 가지고 있다.
사용자의 이전 요청 상태를 기억할 수 있지만, 서버 장애나 확장 시 상태 관리가 어렵다.

Stateless 서버는 요청마다 필요한 정보를 포함해서 처리하고 서버는 상태를 보관하지 않는다.
확장성과 장애 대응에는 유리하지만, 인증 토큰이나 외부 저장소를 잘 설계해야 한다.

통신 도메인에서는 세션 상태 관리가 중요한 경우가 많아서, 상태를 어디에 저장하고 어떻게 복구할지까지 중요해질 수 있다.

## 결론

텔코웨어는 일반 쇼핑몰/커머스 백엔드 회사처럼 CRUD만 보는 느낌은 아닐 가능성이 크다.
공고는 Web Application 백엔드지만, 회사 기반이 IMS, 5G/LTE Core, Cloud, 통신 서버 쪽이라서 필기에서 네트워크, 동시성, 트랜잭션, 장애 안정성을 같이 볼 수 있다.

준비 방향:

1. Java/Spring 기본기를 먼저 잡는다.
2. DB 트랜잭션/인덱스를 본다.
3. TCP/UDP, HTTP, L4/L7, timeout/retry 같은 서버 안정성 문제를 추가로 본다.

현업에서 배치, 트랜잭션 분리, 외부 API 연동, 검증 상태 관리, 운영 DB/통계 DB 분리 경험이 있으므로 필기 후 면접에서는 이쪽으로 연결하면 좋다.

면접 연결 문장:

> 저는 단순 기능 구현보다 운영 안정성, 트랜잭션 범위, 장애 격리까지 고려한 경험이 있습니다.
