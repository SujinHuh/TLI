# 텔코웨어 수진 업무 기반 추가 예상문제

## 목적

이 문서는 텔코웨어 1차 필기시험에서 바로 나오기보다는, 필기 서술형 또는 이후 기술면접으로 이어질 가능성이 높은 수진 업무 경험 기반 질문을 따로 분리한 것이다.

필기 직전에는 Java, Spring, DB, Network를 우선 보고, 이 문서는 서술형 대비와 기술면접 연결용으로 본다.

## 핵심 준비 키워드

- Spring Batch 구조
- Chunk vs Tasklet
- `REQUIRES_NEW`
- MyBatis 동작 원리
- FeignClient
- Parquet
- MSA
- S3
- Aurora MySQL
- 운영DB/통계DB 분리 이유
- DB를 물리 분리한 이유
- 실패 격리 전략
- 트랜잭션 전파 속성
- service_id 단위 처리
- Schema Validation
- reset 로직 개선

## 성능 개선 경험

1. 운영 DB와 통계 DB를 분리한 이유를 설명하시오.
2. 통계성 조회나 배치가 운영 DB에 주는 부하를 어떻게 줄였는지 설명하시오.
3. DB를 논리 분리가 아니라 물리 분리했을 때의 장점과 단점을 설명하시오.
4. 통계 DB 분리가 항상 성능 개선으로 이어지는지 설명하시오.
5. 운영 DB 부하 감소를 확인하려면 어떤 지표를 봐야 하는지 설명하시오.
6. 대량 데이터 조회 API가 운영 DB에 부하를 줄 때 개선 방안을 설명하시오.
