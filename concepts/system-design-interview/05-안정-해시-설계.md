# 5장 안정 해시 설계

## 한 줄 정의
안정 해시는 서버가 추가되거나 제거되어도 전체 데이터가 크게 흔들리지 않도록, 데이터를 여러 서버에 분배하는 해싱 기법이다.

## 핵심 내용
수평 확장은 서버 한 대의 성능을 키우는 것이 아니라 같은 역할의 서버를 여러 대로 늘려 전체 처리량과 가용성을 높이는 방식이다.

안정 해시는 수평 확장 자체를 의미하지 않는다. 수평 확장된 여러 서버 사이에서 어떤 데이터나 요청을 어떤 서버가 담당할지 정할 때 사용하는 분산 기법이다.

단순한 해싱 방식은 보통 다음처럼 생각할 수 있다.

```text
serverIndex = hash(key) % 서버_개수
```

이 방식은 서버 개수가 고정되어 있을 때는 이해하기 쉽다. 하지만 서버가 추가되거나 제거되면 나누는 값이 바뀌기 때문에 많은 key의 서버 위치가 다시 계산된다.

```text
서버 3대: hash(key) % 3
서버 4대: hash(key) % 4
```

서버 한 대만 추가되어도 많은 데이터가 다른 서버로 이동할 수 있다. 캐시 시스템에서는 대량 캐시 미스로 이어질 수 있고, 저장소에서는 데이터 이동 비용이 커질 수 있다.

안정 해시는 이 문제를 줄이기 위해 해시 공간을 원형 링으로 보고, 서버와 key를 같은 해시 공간에 배치한다.

```text
1. 서버 식별자나 서버 key를 해시해서 해시 링 위에 배치한다.
2. 데이터 key도 해시해서 해시 링 위에 배치한다.
3. key 위치에서 링을 시계 방향으로 탐색한다.
4. 처음 만나는 서버가 해당 key를 담당한다.
```

## 해시 서버
해시 서버는 별도의 서버 종류라기보다, 서버 식별자를 해시해서 해시 링 위에 배치한 서버 노드라고 이해하면 된다.

예를 들어 캐시 서버가 세 대 있다.

```text
Cache Server A
Cache Server B
Cache Server C
```

각 서버의 이름, IP, hostname 같은 식별자를 해시 함수에 넣으면 링 위의 위치가 정해진다.

```text
hash("Cache Server A") -> 20
hash("Cache Server B") -> 75
hash("Cache Server C") -> 140
```

이렇게 링 위에 놓인 서버를 더 정확하게는 서버 노드, 물리 노드라고 부를 수 있다.

## 해시 키
해시 키는 데이터를 어느 서버에 보낼지 정하기 위해 해시하는 데이터 식별자이다.

캐시라면 다음과 같은 값이 key가 될 수 있다.

```text
user:1
product:10
session:abc
```

DB 샤딩이라면 다음 값이 key가 될 수 있다.

```text
userId
orderId
tenantId
```

안정 해시에서는 이 key를 해시해서 링 위의 위치를 구한다.

```text
hash("user:1") -> 50
```

그리고 `50` 위치에서 시계 방향으로 처음 만나는 서버가 해당 key를 담당한다.

```text
20  -> Server A
75  -> Server B
140 -> Server C

user:1의 위치 = 50
50 이후 처음 만나는 서버 = Server B
따라서 user:1은 Server B가 담당
```

## 기본 구현 흐름
오늘 읽은 범위의 기본 구현 흐름은 다음과 같다.

- 서버 key를 균등 분포 해시 함수를 사용해 해시 링에 배치한다.
- 데이터 key의 위치에서 링을 시계 방향으로 탐색하다가 처음 만나는 서버가 key가 저장될 서버가 된다.

다음 학습에서는 이 기본 구현법의 두 가지 문제점부터 이어서 확인한다.

## 예시
안정 해시는 분산 캐시에서 자주 떠올릴 수 있다.

```text
Client
 -> Cache Cluster
    -> Cache Server A
    -> Cache Server B
    -> Cache Server C
```

`user:1`이라는 캐시 key가 들어오면, 시스템은 `user:1`을 해시해서 링 위의 위치를 찾는다. 그 위치에서 시계 방향으로 처음 만나는 캐시 서버가 `user:1` 데이터를 담당한다.

서버가 추가되거나 제거될 때도 전체 key를 다시 배치하는 대신, 영향받는 일부 구간의 key만 이동하게 만드는 것이 안정 해시의 핵심 목적이다.

## 주의할 점
- 안정 해시는 수평 확장 자체가 아니라 수평 확장된 서버들 사이에 데이터를 분배하는 방법이다.
- 해시 서버는 해시를 처리하는 특별한 서버가 아니라 해시 링 위에 배치된 서버 노드로 이해하는 편이 정확하다.
- 해시 키는 데이터를 식별하는 key이며, 해당 key를 해시해서 링 위의 위치를 구한다.
- 서버가 적거나 해시 위치가 고르게 퍼지지 않으면 특정 서버에 데이터가 몰릴 수 있다.
