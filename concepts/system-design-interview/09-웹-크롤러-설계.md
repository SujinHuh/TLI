# 9장 웹 크롤러 설계

## 한 줄 정의

웹 페이지를 자동으로 방문해 내용을 가져오고, 페이지 안의 링크를 찾아 수집을 이어가는 시스템이다.

## 이번 학습 범위

웹 크롤러의 활용 목적과 기본 동작, 1단계 문제 이해 및 설계 범위 확정, 2단계 개략적 설계와 작업 흐름을 살펴봤다.

3단계에서는 DFS와 BFS의 방문 순서 차이까지만 간단히 확인했다. 상세 설계는 내일 이어서 공부한다.

## 쉬운 ver

학교 홈페이지에서 자료를 모으는 로봇을 생각하면 된다.

처음에 학교 홈페이지 주소를 알려주면, 로봇은 그 페이지를 가져와 읽는다. 그 안에서 공지사항과 학과 소개 링크를 발견하면 다음에 방문할 목록에 적는다. 이후 목록에서 주소를 꺼내 같은 과정을 반복한다.

- **시작 URL 집합:** 처음 가보라고 알려주는 주소 목록
- **미수집 URL 저장소:** 앞으로 방문할 주소를 적어두는 대기 목록
- **콘텐츠 저장소:** 가져온 페이지 내용을 보관하는 곳

시작 주소가 구글 검색에 등록되어 있어야 하는 것은 아니다.

## 개발자 ver

### 활용 목적

| 목적 | 설명 |
|---|---|
| 검색 엔진 인덱싱 | 검색에 사용할 페이지를 수집한다. 수집한 내용을 검색하기 좋게 정리하는 인덱싱과 구분한다. |
| 웹 아카이빙 | 나중에 사용할 수 있도록 웹 자료를 장기 보관한다. |
| 웹 마이닝 | 수집한 자료를 분석해 유용한 지식을 도출한다. |
| 웹 모니터링 | 웹의 변화나 특정 사례를 확인하는 데 수집 결과를 활용한다. |

수집 자체가 곧 인덱싱이나 마이닝인 것은 아니다.

### 1단계: 문제 이해 및 설계 범위 확정

크롤러를 왜 만들고, 무엇을 얼마나 수집하고 보관할지 정하는 단계다.

| 항목 | 책에서 정한 조건 |
|---|---|
| 목적 | 검색 엔진 인덱싱 |
| 수집 규모 | 매달 웹 페이지 10억 개 |
| 수집 대상 | 새로 생긴 페이지와 수정된 페이지 |
| 보관 기간 | 5년 |
| 중복 콘텐츠 | 중복된 내용을 가진 페이지는 무시해도 됨 |

검색 엔진 인덱싱은 **목적**, 5년 저장은 **보관 조건**이다.

### 2단계: 개략적 설계안 제시 및 동의 구하기

필요한 구성요소와 데이터가 이동하는 순서를 큰 그림으로 정하고 합의한다.

| 구성요소 | 역할 |
|---|---|
| 시작 URL 집합 | 수집의 출발점 제공 |
| 미수집 URL 저장소 | 앞으로 수집할 주소 관리 |
| HTML 다운로더 | 웹 페이지 가져오기 |
| 도메인 이름 변환기 | 도메인 이름에 해당하는 IP 주소 조회 |
| 콘텐츠 파서 | 페이지 구조를 읽고 형식 검증 |
| 중복 콘텐츠 검사 | 이미 저장된 내용인지 확인 |
| 콘텐츠 저장소 | 페이지 내용 보관 |
| URL 추출기 | 페이지 안의 링크 추출 |
| URL 필터 | 수집 대상이 아닌 주소 제외 |
| 중복 URL 검사 | 이미 방문했거나 대기 중인 주소인지 확인 |
| URL 저장소 | 중복 확인에 사용할 주소 기록 |

### URL 필터의 기준

크롤러를 만드는 사람이 수집 목적과 범위에 맞춰 기준을 정한다.

예를 들어 학교 공지사항만 수집한다면 허용할 사이트와 경로를 정하고, 외부 광고 링크나 수집하지 않을 파일 형식을 제외할 수 있다.

검색 엔진에 이미 등록되었는지를 기준으로 거르는 것은 아니다. 주소만으로 실제 내용이나 파일 유형을 알 수 없는 경우에는 응답과 내용을 확인해야 한다.

### URL 중복과 콘텐츠 중복

- **URL 중복:** 같은 주소를 여러 번 발견한 경우다. 동일한 주소를 반복해서 수집 대상으로 등록하지 않도록 확인한다.
- **콘텐츠 중복:** 주소가 달라도 페이지 내용이 같은 경우다. 같은 내용을 여러 번 저장하지 않도록 확인한다.

### DFS와 BFS

- **DFS:** 한 갈래를 먼저 깊게 따라가고, 더 진행할 곳이 없으면 돌아와 다른 갈래를 탐색한다.
- **BFS:** 시작점에서 가까운 단계부터 넓게 탐색한다.

둘의 차이는 방문 순서다. BFS도 계속 진행하면 깊은 곳까지 탐색한다. DFS는 스택이나 재귀, BFS는 큐를 이용해 구현할 수 있다.

### 크롤링과 QA 자동화

페이지에 자동으로 접근한다는 점은 비슷하지만 목적이 다르다.

- 크롤링: 채용공고의 제목·본문·링크를 수집한다.
- QA 자동화: 지원 버튼을 누르면 기대한 화면이 열리는지 검사한다.

크롤러를 이용한 끊어진 링크 검사처럼 두 기능을 함께 활용하는 경우도 있다.

## 예시

```text
시작 주소를 대기 목록에 넣기
    ↓
주소를 꺼내 DNS 조회 후 페이지 가져오기
    ↓
페이지 파싱·검증
    ↓
중복 콘텐츠 확인
    ├─ 중복 → 해당 페이지의 후속 처리 중단
    └─ 새 내용 → 저장
                    ↓
                 링크 추출
                    ↓
             수집 대상 주소 필터링
                    ↓
                 URL 중복 확인
                    ↓
        새 주소를 기록하고 대기 목록에 추가
                    ↓
             다음 페이지 수집 반복
```

## 주의할 점

- URL 추출기는 링크를 찾는 역할이며, 콘텐츠 저장 여부를 결정하는 담당과 구분한다.
- 이미 방문한 주소가 무조건 미수집 목록으로 들어가는 것은 아니다.
- 수정된 페이지를 다시 수집하기 위한 재방문 정책은 별도로 필요하다.
- 오늘은 전체 흐름을 공부한 것이며, 상세 설계나 구현을 완료한 기록은 아니다.
