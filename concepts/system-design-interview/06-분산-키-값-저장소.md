# 6장 분산 키-값 저장소

## 한 줄 정의
분산 키-값 저장소는 키로 값을 조회하는 데이터를 여러 서버에 나누어 저장하고, 장애와 네트워크 단절 상황에서도 요구사항에 맞게 동작하도록 설계한 저장소다.

## 핵심 내용

### 키-값 저장소
키-값 저장소는 고유한 키를 이용해 연결된 값을 저장하고 조회한다.

```text
key -> value
user:100 -> { name: "수진" }
```

키를 통한 단순 조회, 낮은 지연시간, 높은 처리량과 수평 확장이 중요한 경우에 적합하다. 데이터가 많다는 이유만으로 항상 RDB보다 효율적인 것은 아니며, 조인·복잡한 질의·트랜잭션·스키마 요구사항과 데이터 접근 방식을 함께 고려해야 한다.

### 단일 서버의 키-값 저장소
가장 직관적인 방식은 키-값 쌍을 메모리의 해시 테이블에 저장하는 것이다. 조회 속도는 빠르지만 메모리 용량과 비용에 한계가 있고, 별도의 영속화가 없으면 서버 종료 시 데이터가 사라질 수 있다.

이 한계를 줄이기 위해 데이터를 압축하거나 자주 사용하는 데이터를 메모리에 두고 나머지를 디스크에 저장할 수 있다. 로그, SSTable, LSM Tree 같은 디스크 기반 영속화 구조도 사용할 수 있다.

### 분산 해시 테이블과 데이터 파티셔닝
한 서버의 저장 용량이나 처리량을 넘으면 키-값 데이터를 여러 서버에 나눌 수 있다. 분산 해시 테이블은 키를 해시해 키 공간의 위치와 담당 노드를 정한다.

```text
key -> hash(key) -> 담당 노드
```

이처럼 서로 다른 키의 담당 서버를 나누는 것을 데이터 파티셔닝 또는 샤딩이라고 한다. `1~20은 A 서버`처럼 연속 구간으로 나누는 범위 파티셔닝도 있지만, 분산 해시 테이블은 일반적으로 해시값을 이용하므로 키가 연속 번호 순서대로 배치된다는 뜻은 아니다.

### 데이터 복제
복제는 동일한 키-값의 사본을 다른 노드에도 저장하는 별도의 기법이다.

```text
user:1
├── A 노드: 주 데이터
└── B 노드: 복제본
```

실제 분산 키-값 저장소는 보통 데이터를 먼저 파티셔닝하고, 장애에 대비해 각 데이터나 파티션을 정해진 복제 계수만큼 일부 다른 노드에 복제한다.

### CAP 정리
CAP은 다음 세 가지 요구사항을 다룬다.

- 일관성(Consistency): 성공적으로 완료된 최신 쓰기가 이후 읽기에 보이는 강한 일관성
- 가용성(Availability): 장애가 발생하지 않은 노드가 받은 모든 요청에 유한한 시간 안에 오류가 아닌 응답을 반환하는 성질
- 파티션 감내(Partition Tolerance): 노드 사이의 메시지 유실이나 네트워크 단절 상황을 감내하는 성질

CAP을 `항상 세 가지 중 하나를 포기해야 한다`라고만 이해하면 부정확하다. 정확하게는 네트워크 파티션이 발생한 동안 파티션을 감내하는 분산 시스템은 강한 일관성과 가용성을 동시에 완벽하게 보장할 수 없다는 뜻이다. 네트워크가 정상일 때는 일관성과 가용성을 함께 제공할 수 있다.

- CP 시스템: 최신성을 확인할 수 없는 일부 요청을 거절하거나 대기시켜 일관성을 우선한다.
- AP 시스템: 오래된 값이나 일시적인 충돌 가능성을 허용하면서 요청에 계속 응답해 가용성을 우선한다.
- CA 시스템: 네트워크 파티션이 없다는 전제에서는 일관성과 가용성을 함께 제공할 수 있지만, 실제 분산 네트워크에서는 파티션을 완전히 배제하기 어렵다.

### 서로 다른 두 파티션

| 구분 | 의미 |
|---|---|
| 데이터 파티셔닝 | 키-값 데이터를 여러 서버에 나누어 배치하는 것 |
| CAP의 네트워크 파티션 | 서버 사이의 통신이 끊기거나 메시지가 유실된 상태 |

데이터 파티셔닝은 데이터 배치 방법이고, CAP의 파티션은 네트워크 장애 상태이므로 서로 다른 개념이다.

## 예시
A 노드와 B 노드가 같은 키의 데이터를 가지고 있는데 네트워크가 끊겼다고 가정한다. 네트워크 단절 후 A 노드에서 값이 `200`으로 갱신됐지만 B 노드에는 변경된 값이 전파되지 않았다.

```text
A 노드: user:1 = 200
        네트워크 단절
B 노드: user:1 = 100
```

B 노드는 A 노드에 최신값을 확인할 수 없다.

- CP 정책이라면 최신성을 확인할 수 없는 요청을 거절하거나 대기시킨다.
- AP 정책이라면 오래된 값일 수 있는 `100`을 응답하고, 나중에 동기화하거나 충돌을 해결한다.

CAP은 데이터를 어느 서버에 배치할지를 설명하는 이론이 아니라, 이렇게 네트워크가 단절된 동안 어떤 보장을 우선할지 설명하는 정리다.

## 주의할 점
- 분산 해시 테이블은 데이터 배치 방법이고 CAP은 네트워크 단절 상황의 제약이다.
- 데이터 파티셔닝과 CAP의 네트워크 파티션을 혼동하지 않는다.
- 샤딩은 서로 다른 키를 나누어 저장하고, 복제는 같은 데이터의 사본을 저장한다.
- `CAP에서 세 가지 중 두 가지만 고른다`는 표현은 입문용 단순화다.
- CA는 파티션이 없다는 전제에서는 가능하지만, 실제 분산망에서는 네트워크 파티션을 배제하기 어렵다.
