# 7장 분산 시스템을 위한 유일 ID 생성기

## 한 줄 정의
분산 시스템의 유일 ID 생성기는 여러 서버와 데이터베이스가 동시에 동작해도 시스템 전체에서 충돌하지 않는 ID를 발급하기 위한 장치다.

## 핵심 내용

### Auto Increment
Auto Increment는 데이터베이스가 특정 테이블의 새 행에 `1, 2, 3...`처럼 증가하는 값을 자동으로 부여하는 기능이다. 같은 테이블에서 PK 또는 UNIQUE 제약과 함께 사용하면 간단히 중복되지 않는 값을 발급할 수 있다.

분산 환경이라고 해서 Auto Increment가 무조건 중복되는 것은 아니다. 여러 데이터베이스가 서로 조정하지 않고 같은 범위의 번호를 독립적으로 발급할 때 충돌할 수 있다.

```text
DB A -> id 1
DB B -> id 1
결과 -> 시스템 전체에서는 중복
```

### UUID
UUID는 중앙 발급 서버 없이 각 서버에서 독립적으로 만들 수 있고, 서로 충돌할 가능성이 매우 낮다. 따라서 여러 서버가 동시에 ID를 만들어야 하는 환경에서 사용할 수 있다.

다만 일반적인 UUID는 길고 사람이 읽기 어려우며, 생성 순서가 시간 순서와 일치하지 않을 수 있다. 무작위성이 큰 값을 데이터베이스 PK와 인덱스로 사용하면 저장 공간과 인덱스 성능도 함께 고려해야 한다.

### Ticket Server
Ticket Server는 콘서트 예매 시스템이 아니라 번호표 발급기처럼 중앙에서 ID를 발급하는 서버를 뜻한다. 중앙 데이터베이스의 Auto Increment를 이용하면 여러 애플리케이션 서버에 중복되지 않는 번호를 제공할 수 있다.

```text
애플리케이션 A ─┐
                 ├─> Ticket Server -> 101, 102, 103...
애플리케이션 B ─┘
```

구조가 단순하고 숫자 ID를 순서대로 발급할 수 있지만, 중앙 서버에 요청이 몰리면 병목이 될 수 있다. 서버가 하나뿐이면 장애 발생 시 ID 발급 전체가 멈추는 단일 장애점이 될 수도 있다.

## 예시
주문 서버가 여러 대이고 각 서버가 독립된 데이터베이스에서 Auto Increment를 사용하면 같은 주문 ID가 만들어질 수 있다. UUID를 각 서버에서 생성하거나 Ticket Server에서 번호를 중앙 발급하면 시스템 전체의 ID 충돌을 줄일 수 있다.

어떤 방식을 선택할지는 숫자 형식과 정렬 필요성, 발급량, 저장 공간, 장애 대응 방법을 함께 고려해야 한다.

## 주의할 점
- 분산 환경이라는 이유만으로 Auto Increment가 즉시 중복되는 것은 아니다. 서로 조정되지 않은 여러 발급기가 같은 범위를 사용할 때 문제가 된다.
- UUID는 충돌이 절대 불가능한 값이 아니라 충돌 확률이 현실적으로 매우 낮은 값이다.
- Ticket Server는 ID를 중앙 발급하는 설계이며, 티켓 예매의 좌석 동시성 문제를 해결하는 방식과는 다르다.
- 유일 ID는 PK로 사용할 수 있지만, 모든 유일 ID가 반드시 데이터베이스 PK인 것은 아니다.
- 이번 기록은 Auto Increment, UUID, Ticket Server를 처음 비교한 범위까지만 다룬다. 다른 분산 ID 생성 방식은 추가 학습 후 보완한다.
