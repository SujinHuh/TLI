# 고가용성과 배포 전략

## 한 줄 정의
고가용성은 시스템이 장애나 배포 상황에서도 가능한 오래 정상 서비스를 제공하도록 설계하는 특성이다.

## 핵심 내용
가용성은 시스템이 정상적으로 사용 가능한 시간의 비율을 의미한다.

```text
가용성 = 정상 동작 시간 / 전체 시간
```

고가용성을 높이려면 서버를 여러 대로 구성하고, 장애가 난 서버로 트래픽이 가지 않도록 하며, 배포 중에도 서비스 중단이 발생하지 않도록 해야 한다.

배포 전략도 가용성에 영향을 준다. 새 버전을 배포할 때 서비스가 멈추거나 오류 응답이 늘어나면 그 시간은 사용자 입장에서 가용성이 떨어진 시간으로 볼 수 있다.

대표적인 배포 전략은 다음과 같다.

- 롤링 배포: 서버를 일부씩 순차적으로 교체한다.
- 블루그린 배포: 기존 환경과 새 환경을 분리하고 트래픽을 전환한다.
- 카나리 배포: 일부 사용자나 일부 트래픽에만 새 버전을 먼저 적용한다.

## 예시
사용자가 계속 접속 중인 서비스에서 모든 서버를 한 번에 내리고 새 버전을 올리면 배포 시간 동안 서비스가 중단된다.

반대로 여러 서버를 두고 로드밸런서가 정상 서버에만 요청을 보내도록 구성하면, 서버 일부를 교체하는 동안에도 나머지 서버가 요청을 처리할 수 있다.

```text
사용자
  -> Load Balancer
    -> Server A, 정상
    -> Server B, 배포 중 제외
    -> Server C, 정상
```

이런 방식은 배포 작업이 전체 시스템 중단으로 이어지지 않도록 도와준다.

## 주의할 점
- 고가용성은 서버를 여러 대 둔다고 자동으로 달성되지 않는다.
- 로드밸런서, Health Check, 장애 감지, 롤백 절차가 함께 필요하다.
- DB, 캐시, 메시지 큐 같은 공통 의존성이 단일 장애 지점이 될 수 있다.
- 배포 전략은 애플리케이션 코드, DB 마이그레이션, 세션 관리와 함께 설계해야 한다.
- 무중단 배포를 목표로 하더라도 잘못된 배포는 오류율 증가로 이어질 수 있다.
