# 블루그린 배포와 무중단 배포

## 한 줄 정의
블루그린 배포는 현재 운영 중인 환경과 새 버전 환경을 분리해 두고, 트래픽을 새 환경으로 전환해 서비스 중단 시간을 줄이는 배포 방식이다.

## 핵심 내용
블루그린 배포에서는 보통 두 개의 환경을 둔다.

- Blue: 현재 사용자가 접속 중인 운영 환경
- Green: 새 버전을 미리 배포해 검증하는 환경

새 버전을 Green 환경에 먼저 배포하고, Health Check와 기본 검증을 통과하면 로드밸런서나 라우팅 설정을 바꿔 트래픽을 Blue에서 Green으로 이동한다.

```text
배포 전
사용자 -> Load Balancer -> Blue

배포 준비
사용자 -> Load Balancer -> Blue
                         -> Green, 새 버전 대기

전환 후
사용자 -> Load Balancer -> Green
```

문제가 생기면 트래픽을 다시 Blue로 돌릴 수 있어 롤백이 빠르다.

무중단 배포는 사용자가 배포 중 서비스 중단이나 오류를 느끼지 않도록 하는 목표이고, 블루그린 배포는 그 목표를 달성하기 위한 대표적인 전략 중 하나다.

## 예시
AWS에서는 CodeDeploy, Elastic Beanstalk, ECS, ALB Target Group 전환 등을 이용해 블루그린 배포를 구성할 수 있다.

예를 들어 기존 Target Group에는 Blue 서버들이 연결되어 있고, 새 Target Group에는 Green 서버들이 연결되어 있다. Green 서버의 Health Check가 정상이라면 ALB의 트래픽 대상이나 가중치를 Green 쪽으로 바꿔 새 버전을 사용자에게 제공한다.

## 주의할 점
- 블루그린 배포를 사용한다고 항상 100% 무중단이 보장되는 것은 아니다.
- DB 스키마 변경은 기존 버전과 새 버전이 모두 동작할 수 있도록 호환성을 고려해야 한다.
- 세션, 캐시, 장기 연결, 진행 중인 요청을 어떻게 처리할지 설계해야 한다.
- 새 환경이 정상인지 확인하는 Health Check가 부실하면 잘못된 버전으로 트래픽이 넘어갈 수 있다.
- Blue와 Green 환경을 동시에 유지하므로 일시적으로 인프라 비용이 증가할 수 있다.
