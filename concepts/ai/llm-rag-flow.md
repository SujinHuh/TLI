# LLM과 RAG의 기본 흐름

## 한 줄 정의
LLM은 문맥을 바탕으로 텍스트를 생성하는 언어 모델이고,
RAG는 외부 자료를 검색해 그 내용을 모델의 답변 생성에 활용하는 방식이다.

## 이번 학습 범위
토큰 처리와 일반적인 벡터 검색 기반 RAG의 전체 흐름을 살펴봤다.
구현이나 내부 원리를 깊이 공부한 기록은 아니며,
오늘 대화에서 구분한 개념을 복습용으로 정리했다.

## 쉬운 ver
LLM은 입력된 글을 토큰이라는 단위로 처리하고,
앞의 문맥을 바탕으로 다음에 올 내용을 생성한다.

RAG는 질문에 답하기 전에 참고할 자료를 찾아주는 방식이다.
긴 문서를 작은 조각으로 나누어 준비해두고,
질문과 관련 있는 조각을 찾아 LLM에 함께 전달한다.

## 개발자 ver

### LLM과 토큰
- 토크나이저는 텍스트를 토큰으로 나누고 토큰 ID로 변환한다.
- 토큰은 단어와 항상 일치하지 않는다. 단어의 일부나 기호 등이 될 수 있다.
- 모델은 토큰의 수치 표현과 문맥을 처리한다.
- 일반적인 자기회귀 언어 모델은 다음 토큰을 순차적으로 생성한다.
- 텍스트를 토큰으로 나누는 것 자체가 의미 이해의 전부는 아니다.

### 청킹과 임베딩
- 청킹: 문서를 검색에 활용할 작은 조각으로 나누는 작업이다.
- 청크: 나누어진 문서 조각 하나다.
- 임베딩: 텍스트를 숫자 벡터로 표현하는 과정이다.
- 청크는 검색용 문서 조각이고, 토큰은 모델이 텍스트를 처리하는 단위다.
  청크 하나에는 여러 토큰이 들어갈 수 있다.

### 자료 준비 흐름
문서 → 청킹 → 각 청크 임베딩 → 벡터와 원문 청크의 연결 정보 저장

벡터 데이터베이스나 인덱스는 유사한 벡터를 찾는 데 쓰인다.
원문 청크는 같은 저장소에 두거나 별도 저장소에 두고 ID로 연결할 수 있다.
문서명, 페이지, 출처 같은 정보는 메타데이터로 함께 관리할 수 있다.

### 질문 처리 흐름
질문 → 질문 임베딩 → 관련 벡터 검색 → 연결된 원문 청크 조회
→ 질문과 원문 청크를 LLM에 전달 → 답변 생성

검색기(Retriever)는 관련 자료를 가져오는 역할을 한다.
LLM 자체를 검색하는 것이 아니라, 답변에 참고할 자료를 검색한다.
기본 흐름에서는 미리 준비한 청크를 가져온다.

## 예시
“휴가 신청은 어떻게 하나요?”라는 질문이 들어오면,
준비된 사내 규정에서 관련 문단을 검색한다.
질문과 그 문단을 LLM에 전달해 답변을 생성한다.
이는 흐름을 설명하기 위한 예시이며, 직접 구현한 내용은 아니다.

## 주의할 점
- 일반적으로 문서를 먼저 청킹하고 각 청크를 임베딩한다.
- 토큰화와 청킹은 목적과 단위가 다르다.
- RAG는 마지막 단계의 저장소 이름이 아니라 검색과 생성을 결합한 방식이다.
- 모든 RAG가 벡터 검색만 사용하는 것은 아니다.
- 검색 자료가 부정확하거나 모델이 잘못 해석하면 답변도 틀릴 수 있다.
