# DB 락의 종류와 동작

## 한 줄 정의
DB 락은 동시에 접근하는 트랜잭션들 사이에서 데이터 충돌을 조절하기 위해 사용하는 동기화 장치다.

## 핵심 내용
- 공유락은 읽기 위주의 접근에 사용된다.
- 배타락은 수정 작업에 사용된다.
- 락은 데이터 정합성을 지키는 대신 동시성을 낮출 수 있다.
- 실제 락 동작은 DBMS와 쿼리 형태, 인덱스 유무에 따라 달라진다.

### 락 종류
- 공유락: 여러 트랜잭션이 함께 읽을 수 있게 허용하는 락
- 배타락: 다른 트랜잭션의 읽기 또는 쓰기를 제한하는 락
- 갭락: 특정 값 사이의 구간을 잠그는 락
- 의도락: 상위 범위에 락이 걸려 있음을 알리는 락

### SQL과 락
- `SELECT`: 보통 일반 조회는 강한 락을 잡지 않거나 DBMS 설정에 따라 다르게 동작한다.
- `SELECT FOR UPDATE`: 수정 가능성을 전제로 배타적인 락을 건다.
- `UPDATE`: 대상 행에 배타락이 걸린다.
- `INSERT`: 새 행을 넣는 과정에서 충돌 방지를 위해 구간 락이나 관련 락이 걸릴 수 있다.
- `DELETE`: 대상 행에 배타락이 걸린다.

## 예시
재고 차감 같은 작업에서 같은 행을 동시에 수정하면 충돌이 생길 수 있으므로, 락이나 더 강한 격리 수준이 필요하다.

## 주의할 점
- 락을 과하게 잡으면 대기와 병목이 생긴다.
- 인덱스가 없으면 예상보다 넓은 범위에 락이 걸릴 수 있다.
- 배치 작업은 트랜잭션 범위가 길어질수록 락 문제가 커질 수 있다.
- MySQL, PostgreSQL, Oracle, SQL Server는 락 세부 동작이 다르다.
