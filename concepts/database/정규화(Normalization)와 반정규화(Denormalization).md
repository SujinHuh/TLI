# 정규화(Normalization)와 반정규화(Denormalization)의 이해

데이터베이스 설계 시 데이터의 중복을 줄이고 무결성을 지킬 것인지(정규화), 아니면 시스템의 조회 성능을 극대화할 것인지(반정규화)의 설계 방향 차이를 설명합니다.

---

## 1. 정규화 (Normalization) 
**"데이터 중복을 제거하여 무결성(일관성)을 지키기 위해 테이블을 쪼개는 과정"**

* **목적**: 
  * 데이터 중복 최소화.
  * 삽입/수정/삭제 시 발생하는 **이상 현상(Anomaly)** 예방.
* **동작**: 테이블을 1정규형, 2정규형, 3정규형, BCNF 등으로 단계별로 분해(Decomposition)합니다.
* **장점**:
  * 데이터의 일관성과 정합성(무결성)이 유지됩니다.
  * 테이블의 크기가 작아져 수정/삭제 작업이 빠르고 효율적입니다.
* **단점**:
  * 테이블이 여러 개로 쪼개지기 때문에, 데이터를 모아서 보려면 **JOIN**을 많이 사용해야 합니다.
  * JOIN이 너무 많아지면 **조회(SELECT) 성능이 저하**될 수 있습니다.

---

## 2. 반정규화 (Denormalization, 역정규화)
**"조회 성능을 향상시키기 위해, 의도적으로 정규화를 위배하고 데이터 중복을 허용하는 과정"**

* **목적**: 
  * 시스템의 **조회(SELECT) 속도 향상**.
  * 잦은 JOIN으로 인한 성능 저하 해결.
* **동작**: 테이블을 다시 합치거나, 컬럼을 중복해서 추가하거나, 통계값을 미리 계산해 저장하는 등의 기법을 씁니다.
* **장점**:
  * JOIN이 줄어들어 단순하고 빠른 **조회(SELECT) 성능**을 냅니다.
* **단점**:
  * 데이터가 중복 저장되므로 디스크 용량이 더 필요합니다.
  * 수정/삭제 시 중복된 곳을 모두 업데이트해야 하므로 **쓰기 성능이 저하**됩니다.
  * 관리를 잘못하면 데이터 간의 일관성이 깨질 위험(정합성 문제)이 있습니다.

---

## 3. 정규화 vs 반정규화 핵심 비교

| 비교 항목 | 정규화 (Normalization) | 반정규화 (Denormalization) |
| :--- | :--- | :--- |
| **핵심 목표** | 데이터 일관성 및 무결성 유지 | 데이터 조회(SELECT) 속도 향상 |
| **주요 방법** | 테이블을 여러 개로 분해 | 테이블 병합, 컬럼 중복, 통계 테이블 추가 |
| **중복 데이터** | 없음 (최소화) | 있음 (의도적 허용) |
| **JOIN 발생** | 많음 (성능 저하 가능성) | 적음 (성능 향상) |
| **성능 우위** | **쓰기/수정/삭제**에 유리 | **조회(Read)**에 유리 |
| **주사용 환경** | OLTP (실시간 트랜잭션 빈번) | OLAP / 통계 및 대용량 조회 시스템 |

---

## ✍️ 요약 노트 (노션 복사용)

1. **정규화**: 중복 제거, 무결성 중심, **테이블 쪼개기**, **쓰기(CUD) 성능** 유리, 조인은 많아짐.
2. **반정규화**: 성능 향상 중심, **데이터 중복 허용**, **조회(R) 성능** 유리, 데이터 정합성 깨질 위험 있음.
3. **실무 팁**: 처음에는 정규화를 원칙으로 잘 설계한 뒤, 시스템 운영 중 성능 병목이 생기는 특정 화면/API에 한해 부분적으로 반정규화를 적용하는 것이 바람직합니다.
