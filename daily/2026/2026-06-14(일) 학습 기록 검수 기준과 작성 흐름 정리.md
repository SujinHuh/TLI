# 📅 2026-06-14(일) 학습 기록 검수 기준과 작성 흐름 정리

## 🎯 목표
TLI 학습 기록을 문서화할 때 검수 기준과 작성 흐름을 분리해서 정리한다.

## ✅ 완료
- `daily`와 `concepts`를 문서화하기 전에 원문 대조를 수행하는 흐름을 정리했다.
- 검수는 작성자와 분리된 별도 역할(서브 에이전트)이 반드시 수행하도록 합의했다.
- 서브 에이전트 검수 결과를 작성자가 반영한 뒤, 수정본을 다시 보여주는 순서로 정리했다.
- `workflow`가 `verification`을 참조하고, `verification`은 별도 검수 기준 문서로 유지하는 구조를 정리했다.
- 검수 기준은 느슨하게 두지 않고 더 빡빡하게 가져가기로 했다.
- 검수자 프롬프트를 별도 섹션으로 남겨, 원본 대화와 최종 요약 결과물을 5개 기준과 원문 대응 기준으로 비교하도록 정리했다.
- `작성자`라는 표현을 사용해서 문서의 표현을 통일했다.
- 하네스 프로그래밍에서는 실제 사용하는 코드처럼 빡빡하게 검수했는데, TLI에서는 나중에 다시 볼 공부 기록임에도 검수가 느슨할 수 있다는 점을 다시 생각하게 되었다.
- 같은 에이전트가 확인하면 오류가 생길 수 있다고 보고, 검수는 더 빡빡하게 해야 한다고 다시 정리했다.
- 초기 판단을 그대로 두지 말고 검수를 강하게 가져가자는 생각을 다시 추가했다.
