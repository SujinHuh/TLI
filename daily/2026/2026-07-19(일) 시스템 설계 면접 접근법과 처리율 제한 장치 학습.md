# 📅 2026-07-19(일) 시스템 설계 면접 접근법과 처리율 제한 장치 학습

## 🎯 목표
- 가상 면접 사례로 배우는 대규모 시스템 설계 기초 3장 정리
- 4장 처리율 제한 장치 설계 학습 시작

## ✅ 완료
- 3장에서 시스템 설계 면접을 위한 4단계 접근법 정리
  - 문제 이해 및 설계 범위 확정
  - 개략적인 설계안 제시 및 동의 구하기
  - 상세 설계
  - 마무리
- 시스템 설계 면접은 정답을 빠르게 맞히는 퀴즈가 아니라, 요구사항과 가정을 확인하며 면접관과 함께 설계를 좁혀가는 과정이라는 점 정리
- 면접 중 해야 할 것과 하지 말아야 할 것 정리
  - 요구사항을 질문으로 확인하기
  - 스스로 내린 가정을 확정하지 않기
  - 사고 흐름을 면접관이 이해할 수 있게 설명하기
  - 개략적 설계 후 중요한 컴포넌트부터 상세 설계하기
  - 막히면 힌트를 요청하고 침묵하지 않기
- 4장 처리율 제한 장치의 설계 학습 시작
- 처리율 제한 장치가 클라이언트나 서비스가 보내는 트래픽의 처리율을 제어하는 장치라는 점 정리
- 처리율 제한 장치의 목적 정리
  - DoS 공격으로 인한 자원 고갈 방지
  - 서버 비용 절감
  - 우선순위가 높은 API에 더 많은 자원 할당
  - 제3자 API 사용 비용 통제
- 처리율 제한 장치 설계 요구사항 정리
  - 설정된 처리율을 초과하는 요청을 정확히 제한
  - 낮은 응답 시간 유지
  - 적은 메모리 사용
  - 분산 환경에서 여러 서버나 프로세스가 공유 가능
  - 제한된 요청에 대한 명확한 예외 처리
  - 높은 결함 감내성
- 처리율 제한 장치를 어디에 둘 수 있는지 정리
  - 클라이언트 측은 사용자가 통제할 수 있어 위변조나 우회가 가능하므로 안정적인 위치가 아님
  - 서버 측에는 API 서버 내부에 두는 방식과 API 서버 앞단의 미들웨어/API Gateway/Reverse Proxy 등에 두는 방식이 있음
- 처리율 제한을 앞쪽 계층에 둘수록 서버 보호에 유리하지만, API별 정교한 제한에는 인증 정보와 비즈니스 정책을 아는 API Gateway나 애플리케이션 미들웨어가 적합하다는 점 이해
