# 📅 2026-08-26(수) 분산 ID 생성 방식을 비교하고 직접 코드를 짜는 습관을 돌아본 날

## 🎯 목표
- 가상면접 7장 ‘분산 시스템을 위한 유일 ID 생성기’ 이어서 학습

## ✅ 완료
- 단일 데이터베이스의 Auto Increment 방식을 분산 환경으로 확장할 때 고려해야 할 문제 확인
- 분산 환경의 유일 ID 생성 방안으로 다중 마스터 복제, UUID, Ticket Server, Twitter Snowflake의 네 가지 접근 방식이 있음을 확인
- 다중 마스터 복제의 K/offset 방식과 서버 추가·삭제 시 확장 문제 확인
- 다중 마스터 복제도 ID 값만으로 여러 서버 전체의 생성 시간순 정렬을 보장할 수 없다는 점 확인
- UUID는 128비트이며 서버 간 조율 없이 독립적으로 생성할 수 있어 확장이 쉽고 충돌 가능성이 매우 낮지만, 이번 장의 64비트 요구사항과 맞지 않고 UUIDv4의 ID 값만으로는 생성 시간순 정렬을 보장할 수 없다는 점 확인
- Ticket Server가 여러 웹 서버에 중앙에서 고유 ID를 발급하는 구조이며, 중앙 서버가 병목이나 단일 장애점이 될 수 있음을 이해
- 라운드로빈은 사용자 요청을 웹 서버에 분배하고, Ticket Server는 웹 서버에 고유 ID를 발급한다는 차이 확인

## ⏱️ 공부 시간
19:30 ~ 22:00 (총 2시간 30분)

## ✍️ 회고
지금 그 나만의 MVP 모델을 하나 만들고 있고 이거 말고도 코드 관련한 걸 직접 검수 이렇게 직접 그냥 바이브 코딩만 하는 게 아니라 직접 내가 AI 내가 코드를 짜서 AI한테 검수 받는 것도 좀 해야할 필요성을 많이 느꼇다. 내가 생각보다 코드를 많이 짜본 경험이 생각보다 많이 경험이 많이 부족해서 지금 가상 면접 이 책도 읽고 있고 그 다음에 뭐라 그래야 되지 지금 이것도 지금 공부를 하고 있으니까 내 프로젝트도 만들고 있고 그 다음에 지금 이거 뭐야 코드 짜는 연습도 하고 이렇게 쭉 꾸준히 할 생각이다. 그래서 맨날 30분씩 읽어야 하는데 그걸 하지 못하니까 진짜 정말 그 습관대로 들이면서 해야 되겠고 그 다음에 생각보다 그 집에다가 PC 노트북을 켜놓고 회사 가서 바이브 코딩을 좀 하니까 그래도 내가 지금 만드는 MVP 모델을 POC 모델로 작게 작게 모아서 단계별로 향상시키는 거를 지금 구현하고 있어도 너무 빠르게 어느 정도는 모양을 갖춰 나가는 모습이 너무 뿌듯하다. 그리고 내일도 공부를 할 거고 할 거다. 화이팅.
