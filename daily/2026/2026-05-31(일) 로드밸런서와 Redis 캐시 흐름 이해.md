# 📅 2026-05-31(일) 로드밸런서와 Redis 캐시 흐름 이해

## 🎯 목표
REST API 요청이 증가했을 때 로드밸런서와 Redis 캐시가 각각 어떤 역할을 하는지 이해한다.

## ✅ 완료
- REST API 요청 증가 시 로드밸런서를 사용하는 이유 이해
- DNS -> 로드밸런서 -> 애플리케이션 서버 흐름 정리
- ALB와 NLB의 용도 차이 확인
- Health Check가 단순 ping과 어떻게 다른지 이해
- 서버 수평 확장 이후 DB에 요청이 몰릴 수 있다는 점 확인
- Redis를 활용하여 반복적인 DB 조회를 줄이는 흐름 이해
- 캐시와 Redis의 차이 정리
- 로컬 캐시와 분산 캐시의 차이 정리
- Redis 데이터는 용도와 설정에 따라 사라질 수 있다는 점 확인
- 캐시 적용 대상과 TTL을 개발자가 서비스 특성에 맞게 결정한다는 점 정리

## ⏱️ 공부 시간
18:00 ~ 23:00 (총 5시간)

## ✍️ 회고
책으로만 보던 개념들을 회사에서 적용된 프로젝트와 함께 여러 키워드로 살펴보니 구조가 조금씩 이해되기 시작했다.

키워드를 중심으로 공부하는 것도 좋은 방법인 것 같다.

앞으로도 다양한 아키텍처를 경험하고 공부해야겠다고 느꼈다.

로드밸런서에서 Redis 캐시로 이어지는 확장 흐름도 다시 이해할 수 있었다.
