# 📅 2026-06-15(월) 통계 배치와 DB 트랜잭션 개념 정리

## 🎯 목표
- 통계 배치 구조를 바탕으로 DB 트랜잭션, Isolation, Lock 개념 정리
- MySQL의 InnoDB 기준 일반 SELECT, MVCC, row lock 동작 이해
- 통계 DB 분리의 이유를 커넥션, I/O, TEMP, 트랜잭션 유지 시간 관점에서 설명할 수 있게 정리

## ✅ 완료
- ACID의 네 가지 특성 정리
  - Atomicity: 트랜잭션 내 작업은 모두 성공하거나 모두 실패해야 함
  - Consistency: 트랜잭션 전후 데이터가 제약조건과 비즈니스 규칙을 만족해야 함
  - Isolation: 동시에 실행되는 트랜잭션들이 서로의 중간 상태를 침범하지 않도록 보장
  - Durability: 커밋된 데이터는 장애 이후에도 보존되어야 함

- Isolation level 개념 정리
  - Read Uncommitted
  - Read Committed
  - Repeatable Read
  - Serializable
  - MySQL의 InnoDB 기준으로 일반 SELECT는 MVCC 기반 consistent read로 처리될 수 있다는 점을 정리

- MVCC 개념 정리
  - MVCC는 Multi-Version Concurrency Control의 약자
  - row에 대해 여러 시점의 버전을 관리해서 읽기 작업과 쓰기 작업이 서로 덜 막히게 하는 방식
  - 직접 코드에서 사용하는 기능이 아니라 DB 엔진이 일반 SELECT를 처리할 때 내부적으로 사용하는 동시성 제어 방식으로 이해

- Lock 개념 정리
  - 일반 SELECT는 MySQL InnoDB 기준으로 보통 row lock을 직접 잡지 않음
  - SELECT FOR UPDATE, UPDATE, DELETE는 대상 row에 배타 락을 잡을 수 있음
  - 락을 잡는 쿼리에서 인덱스를 제대로 타지 못하면 필요한 row보다 넓은 범위에 lock이 걸릴 가능성이 있음

- 실행계획과 인덱스 개념 정리
  - 실행계획은 DB가 쿼리를 실제로 어떻게 실행할지 보여주는 정보
  - 인덱스를 사용하는지, 테이블 전체를 스캔하는지, 어떤 테이블을 먼저 읽는지, join을 어떻게 처리하는지 확인할 수 있음
  - 쿼리만 보고 인덱스 사용 여부를 단정하지 않고 EXPLAIN을 통해 확인해야 함

- 통계 배치의 DB 자원 사용 관점 정리
  - 배치 쿼리가 오래 실행되면 DB 커넥션을 오래 점유할 수 있음
  - 운영 테이블을 넓게 읽고 join하면 read I/O와 CPU 사용량이 증가할 수 있음
  - 통계 테이블에 insert하면 write I/O, index 갱신, redo/undo log 관리 비용이 발생할 수 있음
  - join, group by, order by가 커지면 TEMP 영역 사용이 증가할 수 있음
  - 긴 트랜잭션은 MVCC snapshot, undo log 등을 더 오래 유지하게 만들 수 있고, 쓰기 작업이 포함된 경우 lock과 로그 관리 부담도 커질 수 있음

- 통계 DB 분리의 의미 정리
  - 문제를 단순히 lock 하나로만 설명하면 부정확할 수 있음
  - 운영 DB와 통계 작업이 같은 DB 자원을 공유하면 커넥션, I/O, TEMP, 트랜잭션 유지 시간 측면에서 부담이 생길 수 있음
  - 운영 DB는 원천 데이터 조회와 서비스 처리에 집중하고, 통계 DB는 집계 결과 저장과 조회에 집중하도록 역할을 분리하는 방향으로 이해
