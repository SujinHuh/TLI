# 📅 2026-07-27(월) 처리율 제한 알고리즘 학습

## 🎯 목표
- 가상면접 4장 처리율 제한 알고리즘 이어서 읽기
- 토큰 버킷, 누출 버킷, 고정 윈도우 카운터 알고리즘의 차이 이해하기
- Cache, Redis, Kafka 개념 복습하기

## ✅ 완료
- 가상면접 4장 처리율 제한 알고리즘 중 토큰 버킷, 누출 버킷, 고정 윈도우 카운터 알고리즘을 학습
- 토큰 버킷 알고리즘은 버킷에 토큰이 남아 있으면 요청을 통과시키는 방식이라는 점 정리
- 토큰 버킷 알고리즘은 구현이 쉽고 메모리 사용 측면에서 효율적이며, 짧은 시간에 집중되는 트래픽도 처리할 수 있다는 점 확인
- 토큰 버킷 알고리즘은 Amazon, Stripe가 API 요청을 통제하기 위해 사용하는 방식이라는 점 확인
- 토큰 버킷 알고리즘은 버킷 크기와 토큰 공급률 두 인자를 적절히 튜닝해야 하며, 이 값 설정이 까다로울 수 있다는 점 정리
- 누출 버킷 알고리즘은 토큰 버킷과 비슷하지만 요청 처리율이 고정되어 있고, 보통 FIFO 큐로 구현한다는 점 정리
- 누출 버킷 알고리즘은 Shopify가 처리율 제한 구현에 사용하는 방식이라는 점 확인
- 누출 버킷 알고리즘은 큐 크기가 제한되어 메모리 사용량 측면에서 효율적이고, 안정적인 출력이 필요한 경우에 적합하다는 점 정리
- 누출 버킷 알고리즘은 단시간에 많은 트래픽이 몰리면 오래된 요청이 큐에 쌓이고, 제때 처리하지 못하면 최신 요청이 버려질 수 있다는 점 확인
- 고정 윈도우 카운터 알고리즘은 타임라인을 고정된 간격의 윈도로 나누고 요청 수를 세는 방식이라는 점 정리
- 고정 윈도우 카운터 알고리즘은 메모리 효율이 좋고 이해하기 쉽지만, 윈도 경계 부근에서 기대한 처리 한도보다 많은 요청이 통과할 수 있다는 점 확인
- 고정 윈도우 카운터 알고리즘은 윈도가 닫히는 시점에 카운터를 초기화하는 방식이 특정 트래픽 패턴을 처리하기에 적합하다는 점 확인
- 이전에 정리한 Cache, Redis, Kafka 개념도 오늘 학습 범위에 포함
